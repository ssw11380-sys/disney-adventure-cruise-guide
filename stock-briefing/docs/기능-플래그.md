# 기능 켜고 끄기 (기능 플래그)

새 기능을 재배포 없이 켜고 끕니다. 문제가 생기면 끄고, 준비되면 켭니다.

## 규칙

- **플래그 목록은 서버 한 곳**: `backend/src/services/featureService.ts` 의 `FEATURES`. 앱에는 목록이 없고 `/api/features` 로 받습니다.
- **기능 하나에 플래그 하나.** 조합이 복잡해지지 않게, 완전히 켠 뒤 한 달이 지나면 플래그를 지우고 코드에 합칩니다.
- **공통 마무리 규칙**: 3-19·3-24 의 새 동작과 P2 기능은 모두 플래그 뒤에 둡니다. 끄면 그 기능의 화면·알림·서버 작업이 0건이어야 하고, 이를 테스트로 확인합니다.
- 결제·가격 관련 코드는 넣지 않습니다(유료화는 나중에 이 구조 위에 따로 결정).

위젯 플래그 네 개(`widgetPolish` 포함)는 홈 화면 위젯이 `/api/features` 를 따로 받지 않으므로 `/api/widget` 응답의 `features` 칸으로도 받습니다(위젯이 쓰는 것만).
응답에 `features` 가 없거나 키가 없으면(예전 서버) 위젯은 그 기능을 꺼진 것으로 봅니다(fallback `false`). 지수·환율 위젯은 이때 짧은 안내만 보입니다.
앱이 떠 있을 때 위젯을 바로 다시 그리면, 앱이 받은 `/api/features` 값과 위젯이 받아 둔 `/api/widget` 값 중 **받은 시각이 늦은 쪽**을 씁니다.
앱의 플래그 캐시는 기기에 며칠 남을 수 있어서(브리핑·설정 화면을 열 때만 다시 받음), 늘 앱 값을 쓰면 끈 기능이 앱을 열 때마다 되살아나기 때문입니다.
위젯이 스스로 갱신할 때도(받아 둔 `/api/widget` 응답을 장중 15분·휴장 2시간까지 다시 쓰거나, 조회에 실패했을 때) 같은 규칙입니다. 마지막으로 그린 값(앱이 적은 것)이 그 응답보다 늦게 받은 것이면 그쪽을 씁니다. 그래서 앱 갱신과 위젯 갱신이 번갈아도 전환 칸·지수 줄이 켜졌다 꺼졌다 하지 않습니다. ↻로 서버에서 방금 받은 값은 늘 그대로 씁니다.

지수는 지수 줄을 그릴 수 있는 새 앱만 받습니다. 새 앱은 `/api/widget?indices=1` 로 묻고, 서버는 이 표시가 있을 때만 지수를 넣습니다(지수 조회도 그때만).
예전 앱(1.3.0)은 쿼리 없이 물으므로 지수 없이 받습니다. 한국 종목만 가진 사용자가 장이 닫힌 뒤에도 나스닥·환율이 바뀌어 304 대신 200 을 받지 않게 하려는 것입니다. 예전 서버는 모르는 쿼리를 무시합니다.

지수·환율 위젯의 판 9개(코스피·코스닥·나스닥·S&P500·다우·필라반도체·원/달러·원/100엔·원/위안)도 같은 규칙입니다.
- 1.4.0 앱은 홈 화면에 지수·환율 위젯이 있을 때만(백그라운드 작업), 또는 그 위젯이 스스로 갱신할 때 `/api/widget?indices=1&board=1` 로 묻습니다. 위젯이 없는 사용자의 응답·ETag 는 예전과 같습니다.
- 지수 줄과 판은 앱 지수 띠(`/api/market/indices?stale=1`)와 같은 목록(같은 30초 캐시·stale 규칙)에서 나오고, 둘을 함께 물어도 지수 출처는 한 번만 부릅니다.
- 앱이 떠 있으면 앱 지수 띠 값으로 바로 다시 그립니다(받은 시각이 늦은 쪽). 조회가 실패하거나 판 없이 받은 응답(다른 위젯의 ↻)이어도 마지막 판을 그대로 두고, 받은 지 3시간이 넘으면 모든 칸을 '지연'으로 그립니다.
- 서버가 `widgetMarket` 을 꺼 두었거나 모르면(롤백한 서버 등 — 물어도 판을 주지 않음) 위젯의 주기·추가·크기 변경 갱신은 받아 둔 응답을 다시 씁니다(다른 위젯과 같은 재사용 규칙, 판을 달라고 계속 묻지 않음).
- 받아 둔 `/api/widget` 응답이 아직 없을 때(업데이트 직후) 첫 조회가 실패하면, 마지막으로 그린 값(앱이 적은 것)의 플래그·지수를 그대로 씁니다. 실패했다고 플래그를 꺼짐으로 보지 않습니다(손익 전환 칸·지수 줄도 같음).

`widgetPnlToggle` 이 켜져 있어도 위젯이 낮아 목록 첫 줄이 들어갈 자리가 없으면, 그 크기에서는 전환 칸(48dp)을 빼고 누적만 보여 줍니다(누르면 앱, 끈 것과 같은 모습). 흔한 4x2(높이 150dp 이상)에서는 목록과 전환 칸이 함께 보입니다.
- 알려진 한계: 4x2 최소 높이(110dp, 100·130%)와 250×130dp(100%)처럼 낮은 크기에서는 손익을 눌러도 앱이 열리고, 위젯에서 당일 손익을 볼 수 없습니다(2x1 자산 위젯의 '오늘'이나 앱에서 봅니다). 머리 줄 48dp + 전환 칸 48dp + 아래 여백이 위젯 높이를 넘거나, 넣으면 목록이 사라지기 때문입니다. 누르는 칸을 합계 줄 위로 겹치는 방법은 실기기에서 누르는 곳이 겹치지 않는지 확인이 필요해 이번에는 하지 않았습니다.
- 손익 칸 설정(누적·당일)은 잔고 위젯 모두가 같이 씁니다. 한 위젯에서 바꾸면 다른 잔고 위젯도 바로 같은 쪽으로 다시 그립니다. 누른 위젯은 늘 보여 주던 쪽의 반대로 바뀝니다(누르는 칸이 보여 주는 쪽을 함께 보냄).

## 바꾸는 법

```bash
# 목록 (기본값·설명·바꾼 값)
curl -H "Authorization: Bearer $API_TOKEN" https://<서버>/api/admin/features
# 끄기 / 켜기 / 기본값으로 되돌리기(null)
curl -X PUT -H "Authorization: Bearer $API_TOKEN" -H "content-type: application/json" \
  -d '{"tossReconcile": false}' https://<서버>/api/admin/features
```

- 서버는 바로 반영하고(바꾼 값은 DB `meta.features` 에 저장, 재시작해도 유지), 앱은 1분 안에 반영합니다.
- 앱은 마지막으로 받은 값을 기기에 저장해, 다음에 켤 때(오프라인 포함) 그 값으로 시작합니다.
- 앱이 아직 한 번도 못 받았거나(첫 실행·예전 서버) 서버가 모르는 플래그는 `useFeature(키, fallback)` 의 fallback 을 씁니다. 새 기능은 `false`(서버가 켤 때만 보이게), 이미 나간 기능을 감싼 플래그는 `true`.
- 서버는 값을 30초 캐시하고(여러 인스턴스·DB 직접 수정도 따라가게), DB 를 못 읽으면 꺼짐으로 봅니다. 앱은 30초마다, 앱으로 돌아올 때마다 다시 받습니다.
- 관리 API 는 앱과 같은 `API_TOKEN` 으로 보호됩니다(다른 `/api/admin/*` 와 같음).

예외: 설정의 '화면 정보' 카드(3-42 1단계, 접는 폰 측정용)는 사용자 요청으로 플래그 없이 넣었습니다. 화면 표시만 하고 서버 작업이 없습니다.

## 새 플래그 추가

1. `FEATURES` 에 `{ default, description }` 한 줄 추가
2. 서버 작업은 `features.enabled("키")`, 앱 화면은 `useFeature("키", fallback)` 과 `gated()` 로 감쌈 (화면 조건마다 따로 거르지 말고 값 하나로)
3. 끈 상태에서 화면·알림·서버 작업 0건 테스트 추가, 위 표 갱신
