## 작업 방법 (단계마다 같은 순서)

1. 코드 → 테스트
   - 서버: `cd stock-briefing/backend && TEST_PG_URL=… REQUIRE_PG=1 npx vitest run`
   - 앱: `cd stock-briefing/app && npm run -s typecheck && npm run -s lint && npx vitest run`
2. 운영 실데이터로 확인합니다(웹 빌드 + 운영 서버).
3. 다크·라이트 전후 캡처를 찍습니다.
4. 독립 리뷰를 받고(서브 에이전트) → 고친 뒤 → 재리뷰합니다.
5. PR → CI 초록 → squash 머지.
   - **KST 08:20~08:40, 15:50~16:15에는 머지하지 않습니다.** 머지하면 Railway가 재배포되어 브리핑 직전에 서버가 재시작됩니다.
6. 배포를 확인하고, 앱이 바뀌었으면 OTA를 냅니다.
   - 명령: `cd stock-briefing/app && EXPO_TOKEN=… npx eas-cli update --channel preview --environment preview --platform android --non-interactive --message "…"`
7. 한국어로 보고합니다. 휴대폰에서 읽기 쉽게, 수치와 스크린샷 중심으로 씁니다.

## 비밀값 (저장소에 없음 — 새 환경에서는 사용자에게 다시 받기)

- **Expo 토큰:** OTA를 낼 때 필요합니다.
- **Railway 토큰:** 배포 상태를 조회할 때 필요합니다.
- **API 토큰:** 운영 서버를 조회할 때 필요합니다.
- **Toss 키, Anthropic 키, BACKUP_KEY:** Railway 변수에만 있습니다.
- **규칙:** 이 값들은 **절대 커밋·출력하지 않습니다.** 커밋 전에는 diff에 토큰 조각이 없는지 검사합니다.
