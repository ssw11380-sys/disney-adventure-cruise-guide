  - 총 평가금액·당일 손익(앱 잔고 화면과 같은 기준)
  - 당일 손익 기여 상위 5 + 그 외 N종목(합 = 당일 손익, 원 단위)
  - 지수(코스피·코스닥·나스닥·S&P500)·원/달러와 환율 효과(당일 손익과 따로)
  - 오늘 일정(한국·미국 장 운영, 미국 정규장 한국 시간, 종목 브리핑이 받아 둔 최근 공시)
- 설명은 모델이 숫자를 옮겨 쓰고, 입력에 없는 숫자·매매·전망 표현이 나오면 숫자로 만든 기본 설명을 씁니다. 모델이 없거나 실패해도 기본 설명으로 저장합니다.
  - 숫자 검사는 값만이 아니라 단위(원·%)와 적힌 부호까지 봅니다. 그래서 '+30,089원'(실제 손실), '약 8%'(실제 -8.06%), '20% 하락'(장 시간 20:00 의 20), '-30,0890원'(틀린 쉼표)은 모두 기본 설명으로 바뀝니다.
  - 개수도 사실과 맞춰 봅니다(2차 검증): '보유 9종목'·'그 외 8종목'·'공시 6건'·'10주'는 사실의 같은 낱말 개수(보유 N종목·그 외 N종목·최근 공시 N건)와 다르면 버립니다. 순위 'N위'는 사실의 기여 순서 번호와만, '4거래일'·'2배'처럼 모르는 말이 붙은 숫자는 지수 값 같은 단위 없는 숫자와만 맞고, '2번째'·'3일 연속' 같은 기간은 늘 버립니다. 예전에는 10 이하 개수를 무조건 봐줬습니다.
  - 부호 없이 말로 방향을 뒤집은 것도 버립니다: 숫자 바로 뒤의 '올랐·상승·이익'(↔ '내렸·하락·손실')이 사실의 부호와 반대면('리게티 컴퓨팅이 8.06% 올랐습니다' ← 실제 -8.06%, '250,267원 이익입니다' ← 실제 손실).
  - 권유·전망 표현도 넓게 봅니다(예상·가능성·반등·기대·비중·좋겠·고려해, 명령·권고형 어미 세요·십시오·시길·바랍니다, 권장·바람직·처분·차익·매집·기회·타이밍, 앞으로·향후·당분간·여력·'것으로 보'·'수 있습니다'·이어질·'내일도' 등). 사실 목록에 있는 공시 제목(주식매수선택권… 등)을 옮긴 것은 괜찮습니다.
  - 상세 화면은 기본 설명으로 바꾼 자세한 이유(모델이 지어낸 숫자·오류 문구)를 보여 주지 않고 "모델 설명이 검사를 통과하지 못해 …" 같은 일반 문구만 씁니다(자세한 이유는 서버 기록과 data 에만).

  - 종목 브리핑이 모두 실패하고 계좌 브리핑만 생긴 세션도 1건입니다. 서버 푸시와 앱 백그라운드(로컬) 알림이 같습니다(위젯 응답에 최근 계좌 브리핑 id `accountIds` 를 더함).

## 작업 방법 (단계마다 같은 순서)

1. 코드 → 테스트
   - 서버: `cd stock-briefing/backend && TEST_PG_URL=… REQUIRE_PG=1 npx vitest run`
   - 앱: `cd stock-briefing/app && npm run -s typecheck && npm run -s lint && npx vitest run`
2. 운영 실데이터로 확인합니다(웹 빌드 + 운영 서버).
3. 다크·라이트 전후 캡처를 찍습니다.
4. 독립 리뷰를 받고(서브 에이전트) → 고친 뒤 → 재리뷰합니다.
5. PR → CI 초록 → squash 머지.
   - **KST 08:20~08:40, 15:50~16:15에는 머지하지 않습니다.** 머지하면 Railway가 재배포되어 브리핑 직전에 서버가 재시작됩니다.
6. 배포를 확인하고, 앱이 바뀌었으면 OTA를 냅니다.
   - 명령: `cd stock-briefing/app && EXPO_TOKEN=… npx eas-cli update --channel preview --environment preview --platform android --non-interactive --message "…"`
7. 한국어로 보고합니다. 휴대폰에서 읽기 쉽게, 수치와 스크린샷 중심으로 씁니다.

## 비밀값 (저장소에 없음 — 새 환경에서는 사용자에게 다시 받기)

- **Expo 토큰:** OTA를 낼 때 필요합니다.
- **Railway 토큰:** 배포 상태를 조회할 때 필요합니다.
- **API 토큰:** 운영 서버를 조회할 때 필요합니다.
- **Toss 키, Anthropic 키, BACKUP_KEY:** Railway 변수에만 있습니다.
