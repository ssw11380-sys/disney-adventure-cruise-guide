## 사용성 개선과 방어적 보완

- `widgetLeanLive` 켜짐: 앱이 받은 시세의 위젯 전달 간격을 60초에서 5초로 단축. 수량·설정·계좌 내용 변경과 앱 이탈은 즉시 전달한다. 이미 받은 자료를 쓰며 추가 외부 조회 없음.
- 느린 위젯 그리기는 하나씩 진행하고 대기 자료는 최신 하나만 보존한다. 오래된 그리기가 나중 자료를 덮어쓰지 않도록 한다.
- 잔고 종목 행에서 누적 시세 손익 보조 줄을 덜어내고 종목명·현재가·전일 등락률을 남긴다. 가격은 중립색, 등락률은 부호와 색상으로 구분한다.
- 지수 위젯은 값·등락률을 남기고 중복 변동 포인트를 생략한다. 지연 경고, 스크롤과 상세 이동은 유지한다.
- 계좌 합계·누적 손익·토스 수신 시각·원가 추정 경고는 숨기지 않는다. 중요한 정확성 안내를 단순 장식으로 취급하지 않는다.
- 기능을 끄면 기존 행 구성·1분 전달을 유지한다. 결함 수정은 유지한다. 예전 위젯 요청의 본문·ETag는 그대로이며 `ms=1` 요청만 새 플래그를 받는다.

## 검증 근거

- 앱 전체: 211개 파일, 3,829개 검사 통과. 타입·린트 통과.
- 서버 로컬: 119개 파일, 2,094개 검사 통과. PostgreSQL 19개는 로컬 환경 없음으로 생략이며 CI에서 필수 실행한다. 타입 검사 통과.
- 모의 화면: 기존 스냅숏 변경 없이 통과. 새 모습의 글자 115%·130%·200%, 등락률·지연 경고·행 이동 보존 검사 포함. 실제 Android 픽셀·터치 관측과 구별한다.
- 관심목록 추가·삭제·기능 해제 구독 통합 검사, 보유 수량·보고서 보존, 새 계좌 사건 및 실패 상태, 늦게 완료된 조회의 시세 역전 방지 검사 포함.
- 최초 새 통합 검사의 DELETE 기대 상태를 기존 API 계약인 204로 바로잡았다. 기존 응답 보존 검사는 새 기능만 준비 단계에서 끄고 원래 기대값을 유지했다. 실패한 스냅숏을 재기록하지 않았다.
- 배포 버전 증가 검사 통과. 프롬프트·분석 모델·브리핑 생성 코드·의존성·네이티브 설정 변경 없음.

## 속도·품질의 범위와 한계

5초는 앱이 이미 받은 자료를 위젯에 넘기는 제한 간격이다. 원본 시세 지연, 네이티브 그리기 시간, Android 백그라운드 실행을 포함하는 완료 시간 보장이 아니다. 계좌 기록의 공급 주기(장중 10분·장 밖 60분 및 체결 사건 후 조회)는 바꾸지 않았다. 공식 계좌 기록을 종목 실시간 추정 평가로 바꾸지 않았다.

수정 전 운영 표본은 Windows PC→Railway 35초/5초 각 1회이며 연결부터 첫 변경 메시지 457ms/223ms였다. 휴대폰 화면 시간이나 평균으로 일반화하지 않는다. 수정 후와 캐시·시장 상황이 같지 않으므로 개선율을 계산하지 않는다.

분석 자료·모델·단계·출력 설정을 줄이지 않았다. 기존 관련 회귀 검사는 통과했지만 새 유료 보고서를 생성해 출력 품질을 비교하지 않았으므로 '품질 동일 실증'으로 표시하지 않는다.
