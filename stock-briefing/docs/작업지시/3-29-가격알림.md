3. 체결(`StreamTick`, `liveTick.ts:5-11`)의 `volume` 은 출처마다 뜻이 다르고(토스 Open API 웹소켓은 그 체결 한 건의 수량), 서버는 **가격이 바뀐 체결만** 보냅니다. 시세의 `volume`(당일 누적)도 스트림 중에는 잘 갱신되지 않습니다(`hooks.ts:126-129` 주석의 알려진 한계). → 체결로 하루 누적 거래량을 셀 수 없습니다. 거래량 급증은 **서버가 30분봉으로** 계산합니다(3.3).

## 3. 동작 규칙

### 3.1 조건 5가지와 저장 값

| kind (API·DB 글자 그대로) | 뜻 | value | 울리는 조건 |
|---|---|---|---|
| `priceAbove` | 가격이 값 이상 | 종목 통화 가격(원 정수 / 달러 센트까지) | `quote.price >= value` |
| `priceBelow` | 가격이 값 이하 | 같음 | `quote.price <= value` |
| `rateUp` | 전일 대비 등락률이 +값% 이상 | 1~30 (소수 둘째 자리까지, 양수로 저장) | `quote.changeRate >= value` |
| `rateDown` | 전일 대비 등락률이 −값% 이하 | 1~30 (양수로 저장) | `quote.changeRate <= -value` |
| `volume` | 거래량이 개장 뒤 같은 경과 시간의 평균보다 값 배 이상 | 2 · 3 · 5 · 10 중 하나 | 서버 `ratio >= value` (3.3) |

- 가격 조건은 **종목 통화**(한국 원, 미국 달러)로 정합니다. 설정의 '원화로 보기'와 상관없습니다(환율이 움직여도 조건이 바뀌지 않게). 서버가 코드로 통화를 정해 `currency` 에 적습니다(`isKrCode` → `KRW`, 아니면 `USD`). 등락률·거래량 조건은 `currency` 가 `null`.
- 한도: 한 종목 5개, 모두 30개, **거래량 조건은 모두 10개**(거래량은 종목마다 30분봉 450개를 30초마다 받으므로 토스 웹 요청을 묶어 두려고). 같은 (종목·kind·value) 는 하나만.
- 조건은 **등록 종목(보유·관심)** 에만 만듭니다 — 스트림이 등록 종목 체결만 보내기 때문입니다(`priceStream.ts`). 등록에서 뺀 종목의 조건은 지우지 않고 **쉬는 중**으로 둡니다(다시 등록하면 다시 확인). 서버는 목록을 줄 때 줄마다 `registered`(지금 `registered_stocks` 에 있는지)를 붙입니다. `StockService` 는 고치지 않습니다.
- **쉬는 중인 조건은 앱이 어떤 길로도 확인하지 않습니다.** 앱에는 등록 종목이 아닌 값이 들어오는 길이 있기 때문입니다: 발견 탭·검색에서 연 미등록 종목 상세 `[apiUrl, "stock", code]` 는 3초마다 새로 받아지고(`useStock`, 미등록 상세는 스트림 주기가 아님 — `hooks.ts:143-155` `streamed()`), 서버가 아직 잊지 않은 삭제 종목의 체결이 올 수도 있습니다(`liveStream.tsx:113` 주석). 그래서 규칙을 순수 함수 하나로 정해 엔진·`ListWatch`·`VolumeWatch` 가 모두 씁니다:
  - `activeRules(rules, listCodes)` = `rule.registered === true` 이고, `listCodes`(이번 실행에서 받은 잔고 목록 `[apiUrl, "stocks"]` 의 코드 모음 — `dataUpdatedAt >= RUN_START` 일 때만, 아니면 `null`)가 있으면 그 안에 코드가 있는 조건. `listCodes === null` 이면 서버 `registered` 만 봅니다.
  - `checkQuoteRules`·`checkVolumeRules` 는 **활성 조건만** 보고, 값이 종목 상세이면 그 데이터의 `registered === false` 일 때도 건너뜁니다(3.2 '울려도 되는 시세' 5번).
  - `VolumeWatch` 의 `codes` 는 **활성 거래량 조건**의 종목만. 서버 `/volume` 은 등록 여부를 보지 않습니다(거르기는 앱이 함 — 시트는 등록 종목에서만 열림).
  - **등록 종목이 바뀌면 조건 목록을 다시 받습니다**: 조건 목록은 주기로 다시 받지 않고(30초 캐시, 앱으로 돌아올 때·실패했을 때만 다시 — 5장 앱 5. 전역 기본은 `refetchOnWindowFocus: false` — `_layout.tsx:49`), 종목 등록·삭제는 `[apiUrl, "stocks"]` 만 무효화합니다(`hooks.ts:614`). 그대로 두면 `registered` 가 옛 값으로 남습니다. 그래서 엔진이 이번 실행에서 받은 잔고 목록의 **코드 모음**(정렬해 이은 글자)을 기억해 두고, 새로 받은 목록의 모음이 앞의 것과 다르면 `qc.invalidateQueries({ queryKey: [apiUrl, "priceAlerts"], exact: true })` 합니다(처음 본 모음은 기억만). 체결은 목록의 줄을 늘리거나 줄이지 않으므로 모음을 바꾸지 않습니다. → 삭제 직후에는 `listCodes` 로 바로 쉬고, 다시 받은 조건 목록의 `registered: false` 로 시트·설정 칸 글(`등록 종목이 아니라 확인하지 않음`)도 바뀝니다.
- 조건은 한 번 울려도 지워지지 않습니다. 다음 거래일에 다시 조건에 맞으면 또 한 번 울립니다(3.4).

### 3.2 가격·등락률: 언제 확인하고 언제 울리나

**확인하는 때** (모두 새 `PriceAlertProvider` 안의 '엔진')
- react-query 캐시 구독 `qc.getQueryCache().subscribe(e => …)` 에서 `e.type === "updated" && e.action.type === "success"` 인 사건만 봅니다(체결이 `setQueriesData` 로 고친 것·폴링으로 받은 것 모두 이 사건). 캐시 사건 안에서 **바로** 확인합니다(타이머·디바운스 없음) → 체결 도착부터 화면 위 알림까지 3초보다 훨씬 짧습니다.
  - `queryKey` 가 `[apiUrl, "stocks"]` 이면 목록의 모든 종목을, `[apiUrl, "stock", code]` 이면 그 종목만 봅니다. 그 밖의 키는 무시합니다. 체결 하나가 목록·상세를 모두 고치면 사건이 두 번 오지만 3.4 의 메모리 기록으로 한 번만 울립니다.
- **이번 실행에서, 앱이 앞에 있는 동안 받은 값만**: 사건의 `e.query.state.dataUpdatedAt >= Math.max(RUN_START, activeSince)`.
  - `RUN_START` = 제공자 모듈을 불러온 때의 `Date.now()`(모듈 전역 — `liveStream.tsx` 의 `SESSION_START` 와 같은 뜻, 그 파일을 고치지 않으려고 따로 둠). 기기에 저장해 둔 옛 목록(몇 시간 전 가격)으로는 울리지 않습니다.
  - `activeSince` = 앱이 마지막으로 `active` 가 된 때(제공자 인스턴스의 `useRef`. 처음 그릴 때 이미 `active` 면 `RUN_START`). 앱이 뒤에 있는 동안 캐시에 들어온 값(뒤로 가기 직전에 도착한 체결 등)은 그때 확인하지 않았으므로, 돌아온 뒤 그 값으로 몇 시간 늦게 '지금 88,700원 · 10:00 기준'이라고 울리지 않게 합니다.
- **앱이 앞에 있을 때만**: `AppState.currentState === "active"` 가 아니면 확인하지 않습니다(기록도 하지 않음 — 뒤에서 올린 알림 목록 줄은 소리 없이 뜨지 않으므로, 3.5). `active` 로 **돌아온 순간에는 캐시를 확인하지 않습니다**: 돌아오면 소켓이 다시 붙어 스냅샷 체결을 보내고(`liveStream.tsx:332-337`) 목록 주기 요청도 다시 돌아(끊김 3~4초·스트림 30초) 새 값이 곧 오므로, 그 새 값(`activeSince` 뒤)으로 확인합니다.
- **엔진이 시작하는 때**: 플래그 켬 + 서버 조건 목록을 **한 번이라도 받음(데이터 있음)** + 기기 기록(3.4)을 읽음 — 셋 다 된 뒤. 그 전의 캐시 사건은 무시하고, 준비되는 순간 '지금 캐시로 한 번 확인'(아래)을 합니다(재시작 직후 서버 기록을 모른 채 울리지 않게).
- **조건 목록이 새로 오면**(조건 목록 쿼리의 `dataUpdatedAt` 이 바뀜 — 저장·지우기 뒤, 등록 종목이 바뀌어 다시 받음(3.1), 실패 뒤 재시도, 앱으로 돌아와 다시 받음) '지금 캐시로 한 번 확인'을 합니다. 체결·폴링이 뜸한 종목도 저장 직후 '바로 한 번'(아래 '이미 맞음')이 늦지 않게 하려는 것입니다.
- **지금 캐시로 한 번 확인** = 잔고 목록 `[apiUrl, "stocks"]` 과 캐시에 있는 종목 상세들(`qc.getQueryCache().findAll({ queryKey: [apiUrl, "stock"] })`)의 값, 그리고 거래량은 마지막 거래량 응답(`[apiUrl, "priceAlerts", "volume", …]`) — 모두 위 `dataUpdatedAt >= Math.max(RUN_START, activeSince)` 를 지키는 값만. 앱이 앞에 없으면 하지 않습니다.

**목록을 늘 받아 두기 (`ListWatch`)**
- 체결은 잔고 목록이 이번 실행에서 받은 값일 때만 목록에 붙고, 잔고 탭이 가려지면 그 화면의 구독이 끊깁니다(`useStocks` 의 `subscribed: focused`, `hooks.ts:157-162`). 그래서 켜져 있고 **활성(3.1) 가격·등락률 조건이 하나라도 있으면** 제공자 안의 작은 부품 `ListWatch` 가 목록을 구독합니다. 이 부품은 `useStocks()` 를 부르지 않고(루트에는 화면 초점이 없음) `useQuery` 를 직접, **`useStocks` 와 같은 옵션**(`hooks.ts:161`, `subscribed` 만 뺌)으로 씁니다:
  ```ts
  /**
   * 가격 조건이 있을 때 잔고 목록을 늘 받아 둔다 (잔고 탭이 가려져도, 소켓이 끊겨도).
   * 잔고 탭(useStocks)과 같은 키·같은 주기라 둘이 함께 있어도 요청은 하나다: 쿼리에 사건이 있을 때마다(받기 시작·받음·체결로 고침)
   * react-query 가 모든 관찰자의 주기 타이머를 같은 순간에 다시 걸고, 먼저 울린 쪽이 받기 시작하면 그 사건이 다른 쪽 타이머를 다시 건다
   */
  function ListWatch() {
    const api = useApi();
    const { apiUrl } = useSettings();
    const every = useLivePoll(); // hooks.ts:133 — 스트림 중 30초 보정·끊기면 3~4초·장 닫힘 1분(pollSaver 5분)
    useQuery({
      queryKey: [apiUrl, "stocks"],
      queryFn: api.listStocks,
      staleTime: 2_000,
      retryDelay: 1_000,
      refetchIntervalInBackground: false,
      refetchInterval: every, // 관찰자 수로 끄지 않는다 (아래)
    });
    return null;
  }
  ```
- **관찰자 수(`getObserversCount()`·`observers`)로 주기를 끄지 않습니다.** 두 가지 까닭입니다:
  1. 루트의 `WidgetBridge`(`WidgetBridge.tsx:27`, 늘 붙어 있음 — `_layout.tsx:157`)와 넓은 창 종목 상세의 `useHoldingsNav`(`lib/holdingsNav.ts:133`)가 같은 키를 `enabled: false` 로 구독하고, 브리핑 탭·알림 설정 칸·첫 실행 확인은 `useRegisteredStocks`(주기 없음, `hooks.ts:256-259`)로 구독합니다. 관찰자 수는 거의 늘 2 이상이라, 수로 끄면 ListWatch 는 한 번도 받지 않고 잔고 탭이 가려진 채 소켓이 끊기면 가격 알림이 조용히 멈춥니다.
  2. react-query 5.103.2 는 다른 관찰자가 빠질 때(`Query.removeObserver` — 잔고 탭이 초점을 잃어 `subscribed: false`) 남은 관찰자의 간격을 다시 계산하지 않습니다. 다시 계산하는 곳은 `onQueryUpdate`·`setOptions` 의 `#updateTimers` 뿐입니다(`node_modules/@tanstack/query-core/src/query.ts` `removeObserver`, `queryObserver.ts` `#updateTimers`). 그래서 '잔고 탭이 떠나면 다시 받기'도 보장되지 않습니다.
- **요청이 두 배가 되지 않는 까닭** (query-core 5.103.2 에서 확인, 7장 테스트가 확인): ① `Query.#dispatch` 는 사건마다 모든 관찰자의 `onQueryUpdate` → `#updateTimers` 를 불러 간격 타이머를 같은 순간에 다시 겁니다. ② 두 관찰자의 간격은 같은 쿼리 상태로 같은 `useLivePoll` 이 계산하므로 같습니다. ③ 먼저 울린 타이머의 `query.fetch` 가 곧바로(동기로) `fetch` 사건을 보내 다른 관찰자의 타이머를 다시 걸고, 받는 중에 다른 관찰자가 받기를 부르면 같은 요청으로 합칩니다(`query.ts` `fetch` 의 `fetchStatus !== 'idle'` 갈래).
- 활성 가격·등락률 조건이 없거나(조건 없음·거래량 조건만·쉬는 중만), 엔진이 준비되지 않았거나(조건 목록을 한 번도 못 받음), 플래그가 꺼져 있으면 이 부품을 그리지 않습니다(요청이 지금과 같음).

**울려도 되는 시세** (다섯 가지 모두 참이어야)
1. `quote` 가 있고 `quote.stale` 이 참이 아님.
2. `quoteDate = tradingDate(quote.asOf, code)` 가 `tradingDate(new Date(nowMs).toISOString(), code)` 와 같음(`app/src/lib/marketTime.ts:180` — 한국은 08:00 전은 전날, 미국은 뉴욕 20:00 부터 다음 거래일, 휴장일은 직전 거래일). 지난 거래일 시세로는 울리지 않습니다.
3. `quote.session` 이 있으면 `session.open === true && session.eligible !== false`(그 종목이 지금 연속 거래 중 — 동시호가·장 마감·휴장·거래정지·대상 아님이면 아님). `session` 이 없는 예전 서버면 `inTradingHours(nowIso, code)`(`marketTime.ts:200`).
4. **그 `session` 이 아직 맞는 값**: `session.until` 이 있고 `Date.parse(session.until) <= nowMs` 이면 울리지 않습니다. `session` 은 마지막으로 **받은** 때의 값이고, 체결(`applyTick`, `liveTick.ts:68-93`)은 가격·등락·`asOf` 만 바꾸고 `session`·`stale` 은 그대로 둡니다. 경계(`until`, 예: 15:20 마감 동시호가) 뒤 다시 받기가 늦거나 실패하면 동시호가·장 마감으로 넘어간 뒤 온 체결에도 `open: true` 가 남으므로, 경계가 지난 `session` 은 믿지 않습니다(다음 받기가 새 `session` 을 주면 그때 확인). `until` 이 `null` 이면 이 검사를 하지 않습니다.
5. **활성 조건·등록 종목 값**: 조건이 `activeRules`(3.1)에 들고, 값이 종목 상세이면 그 데이터의 `registered !== false`.

**울리는 것**: 위를 통과하고 3.1 조건이 참이고, 그 조건이 그 날짜(`quoteDate`)에 아직 울리지 않았으면(3.4) 울립니다. '넘는 순간'만 보는 것이 아니라 **그날 처음 참인 때** 울립니다 → 앱이 꺼져 있던 동안 넘은 조건도 앱을 켜고 첫 확인(새로 받은 목록) 때 한 번 알립니다.
- 저장할 때 이미 참인 조건(예: 지금 +6% 인데 `+5% 이상`)은 저장 뒤 조건 목록을 다시 받은 순간의 '지금 캐시로 한 번 확인'에서 한 번 울립니다(체결을 기다리지 않음). 시트가 저장 전에 안내 줄을 보입니다(4.2 `이미 맞음`). 미리 채운 값(3.7)은 늘 '아직 아닌 쪽'이라 보통은 생기지 않습니다.
- 알림에 적는 숫자는 모두 그 캐시의 시세 값입니다(`quote.price`·`quote.changeRate`·`quote.asOf`·`quote.priceBasis`) — 화면의 시세 머리와 같은 값.

### 3.3 거래량 급증: 시간대 보정 · 데이터 출처 · 근사 표시

**정의**: `ratio = 오늘 정규장 누적 거래량(지금까지) ÷ 지난 거래일들의 '개장 뒤 같은 경과 시간까지' 누적 거래량 평균`. `ratio >= value` 면 울립니다. 로드맵의 '같은 시각까지의 20일 평균 누적 거래량'을 **개장 뒤 경과 시간**으로 맞춘 것입니다(수능일·새해 첫 거래일·미국 조기 폐장·서머타임이 바뀐 주에도 같은 구간끼리 견주려고).

**데이터 출처 (새 출처 없음, 로그인 없음)**: 서버가 이미 쓰는 차트 봉 `StockService.getCandles(code, "30m", 450)`(`stockService.ts:1116`, 봉 캐시 `candleCache.ts` — 분봉은 20초 새 값, 정규장 중 30초까지 재사용). 30분봉은 토스 웹 차트만 줍니다(`toss.ts:525-550`, 한 번에 **450개까지**, 이어 받기 없음 — 토스 Open API 는 30분봉을 만들지 않고 넘기고(`tossOpenApi.ts:488-489`), 네이버·야후는 분봉을 주지 않음). 오늘 누적도 **같은 봉**으로 셉니다(시세의 `volume` 과 섞지 않음 — 출처·구간이 달라 비율이 틀어질 수 있어서).

**정직한 근사 (화면에 그대로 밝힘)**:
- **20거래일이 안 될 수 있음**: 450개 한도 때문에 받은 봉이 덮는 지난 거래일 수(`days`, 최대 20)만 씁니다. 하루 봉 수는 이 PC 에서 확인하지 못했습니다 — 한국 봉이 KRX 정규장만(하루 13개)이면 20일을 채우고, KRX+NXT 통합(08:00~20:00, 하루 24개)이면 약 18일입니다. 화면·알림 글에 **`최근 N거래일`** 로 적습니다. `days < 5` 면 확인하지 않습니다(`short`).
- **봉 안은 고르게 나눠 셈**: 30분봉 안의 거래가 고르게 일어났다고 보고, 지난 날은 같은 경과 시간이 걸친 봉을 비율만큼 셉니다(아래 식). 그래서 **개장 뒤 첫 30분(첫 봉)에는 확인하지 않습니다**(`early`) — 첫 봉에는 시가 단일가(동시호가) 체결이 몰려 고르게 나눠 세는 어림이 크게 틀립니다. 마감 단일가 봉의 치우침은 남습니다(6장 6번).
- **정규장만**: 한국 KRX 정규장(`krRegularHours(date)`, `marketContext.ts:132` — 수능일 10:00~16:30, 새해 첫 거래일 10:00 개장), 미국 09:30 ET ~ `usRegularCloseMinutes(date)`(`marketContext.ts:113` — 조기 폐장 13:00) 동안만 봅니다. NXT 프리·애프터, 미국 프리·애프터·주간거래 거래량은 오늘·지난 날 모두 넣지 않습니다(같은 구간끼리 견줌).
- **늦을 수 있음**: 앱은 거래량 상태를 **30초마다** 묻고(`priceAlert.volumePollMs`), 서버 봉은 최대 30초 묵을 수 있어 조건에 닿은 뒤 **약 1분 안**에 알게 됩니다. '3초'는 앱이 그 응답을 받은 때부터입니다(가격·등락률은 체결 도착부터 3초 안). → 로드맵 완료 기준과 다른 점(8.3)입니다.
- **받기가 실패해도 옛 봉**: `CandleCache` 는 새로 받기가 실패하면 받아 둔 봉을 돌려줍니다(`candleCache.ts:86-89`). 그때는 오늘 누적이 적게 잡혀 비율이 낮아질 뿐(늦게 울림) 잘못 울리지는 않습니다. 받아 둔 봉도 없을 때만 `unavailable` 입니다.

**계산 (서버 순수 함수, 새 파일 `backend/src/services/volumeBaseline.ts`)**:

```ts
import type { Candle } from "../domain/types.js";

export type VolumeState = "ok" | "closed" | "early" | "short" | "unavailable";

export interface VolumeStatus {
  code: string;
  status: VolumeState;
  /** 그 시장의 오늘 날짜 (한국 = 서울, 미국 = 뉴욕). closed 면 null */
  date: string | null;
  /** 오늘 정규장 누적 거래량 (30분봉 합, 지금 봉 포함). ok 일 때만, 아니면 null */
  volume: number | null;
  /** 지난 거래일들의 같은 경과 시간 누적 평균 (반올림한 정수). ok 일 때만 */
  expected: number | null;
  /** volume ÷ (반올림 전 평균), 소수 둘째 자리 반올림. ok 일 때만 */
  ratio: number | null;
  /** 평균에 쓴 지난 거래일 수 (최대 20). ok·short 일 때, 그 밖에는 0 */
  days: number;
  /** 오늘 정규장 개장 뒤 지난 분. closed 면 null */
  minutes: number | null;
  /** 계산한 때 (한국 시간 ISO, seoulIso(now)) */
  asOf: string;
  /** ok 가 아니면 까닭 (한국어, 4.3 표) */
  reason: string | null;
}

/** 봉을 받기 전에: 지금이 그 시장 정규장인지·개장 뒤 30분이 지났는지 (closed·early 면 봉을 받지 않는다) */
export function volumeWindow(code: string, now: Date): { state: "closed" | "early" | "open"; date: string | null; minutes: number | null };

/** 30분봉(오래된 → 최신, time = 봉 시작 ISO)으로 상태. limit = 요청한 봉 개수(450) */
export function volumeStatus(code: string, candles: Candle[], now: Date, limit = 450): VolumeStatus;
```

- 시각: `marketContext.ts:24` 의 `parts(d, tz)`(지금은 파일 안 함수)를 **export 만** 해서 씁니다(동작 그대로). `kr = isKrCode(code)`(`backend/src/lib/codes.ts:15`), `tz = kr ? "Asia/Seoul" : "America/New_York"`.
- 그날 정규장: `hours(d) = kr ? krRegularHours(d) : { open: 9 * 60 + 30, close: usRegularCloseMinutes(d) }`, 거래일: `kr ? isKrTradingDate(d) : isUsTradingDate(d)`(`marketContext.ts:99, :93`).
- `volumeWindow`: `n = parts(now, tz)`. 거래일이 아니거나 `n.minutes < open` 이거나 `n.minutes >= close` → `closed`(date·minutes null). `elapsed = n.minutes − open`, `elapsed < 30` → `early`(date = n.date, minutes = elapsed). 아니면 `open`.
- 봉 나누기: `time` 이 없는 봉은 버림. `p = parts(new Date(b.time), tz)`, `d = p.date`. 거래일이 아니거나 `p.minutes < hours(d).open` 이거나 `p.minutes >= hours(d).close` 인 봉은 버림. 남은 봉은 날짜별로 `offset = p.minutes − hours(d).open` 과 `volume` 을 모음.
- 잘린 날 빼기: `candles.length >= limit` 이면 받은 봉(버리기 전) 중 **`time` 이 있는 맨 앞 봉의 그 시장 날짜** `parts(new Date(first.time), tz).date` 는 앞부분이 잘렸을 수 있어 뺍니다(오늘이면 빼지 않음). **`candles[0].date` 를 쓰지 않습니다**: `date` 는 토스 `dt` 의 앞 10자(`toss.ts` `fetchChart` — `date: dt.slice(0, 10)`)라, 미국 30분봉 `dt` 의 오프셋이 서울이면 뉴욕 10:00 뒤 봉의 `date` 가 다음 날이 되어 **다른 날**(온전한 날)을 빼고 잘린 날을 평균에 넣습니다(7장 J 가 잡음). `time` 이 있는 봉이 하나도 없으면 빼지 않습니다(그때는 쓸 봉도 없어 `short`).
- 오늘: `volume = Σ (오늘 봉 중 offset < elapsed) b.volume` (지금 걸친 봉은 받은 그대로).
- 지난 날: 오늘보다 앞선 날짜를 최근 것부터 **최대 20개**. 날 `d` 의 `cum_d = Σ b.volume × clamp((elapsed − offset) / 30, 0, 1)`. 그날 정규장 봉이 하나도 없으면 그 날짜는 목록에 없습니다(거래 없는 30분 구간은 봉이 없어도 0 으로 셈).
- `days < 5` → `short`(reason `지난 거래일 30분봉이 N일뿐이라 견줄 수 없음`). 평균 `≤ 0` → `short`(reason `지난 거래일 같은 시각 거래량이 0`). 아니면 `ok`, `expected = Math.round(평균)`, `ratio = Math.round((volume / 평균) * 100) / 100`.
- 서비스는 `volumeWindow` 가 `open` 일 때만 봉을 받습니다. 받기가 실패하면(받아 둔 봉도 없음) `unavailable`(reason `30분봉을 받지 못함`). 여러 종목은 **순서대로** 받습니다(한 번에 몰아 보내지 않음, 최대 10종목, 앱이 보낸 차례).
- **시간 예산**: `volume(codes)` 는 시작한 뒤 `volumeBudgetMs`(생성자 선택 값, 기본 **35_000**)가 지나면 남은 종목의 봉을 받지 않고 `unavailable`(reason `시간 안에 30분봉을 받지 못함`)로 돌려줍니다. 시간은 `Date.now()` 로 잽니다(주입된 `now` 는 테스트에서 고정이라 쓰지 않음). 까닭: 토스 웹 요청은 건당 최대 8초(`toss.ts:25` `REQUEST_TIMEOUT_MS`)이고, 봉 캐시는 정규장 중 30초가 넘은 봉은 기다려 새로 받으므로(`candleCache.ts:40-65`) 30초마다 묻는 10종목이 느린 토스에서는 80초까지 걸릴 수 있습니다. 앱 요청 시간 제한은 **45초**(5장 앱 2)라 예산 안에 끝난 응답을 늘 받습니다(예전 15초면 매번 시간 초과 → 거래량 알림이 계속 오지 않을 수 있었음). 알려진 한계: 토스가 계속 느리면 뒤쪽 종목은 그동안 `unavailable`.
- 7장 A~J 의 기대값은 이 식을 그대로 옮긴 시험 코드(`marketContext.ts` 의 실제 휴장·특수일 목록)로 미리 돌려 맞춘 값입니다.

### 3.4 하루 한 번 (중복 막기) · 재시작

- **날짜 열쇠**: 가격·등락률은 `quoteDate`(3.2), 거래량은 서버가 준 `date`.
- **서버 기록 (재시작·다른 실행에도 유지)**: 표 `price_alerts` 의 `fired_on`(그 날짜)·`fired_at`·`fired_value`. 앱은 울린 뒤 `POST /api/price-alerts/:id/fired { date, at, value }` 를 보냅니다. 서버는 **한 문장으로** `update price_alerts set fired_on = ?, fired_at = ?, fired_value = ? where id = ? and (fired_on is null or fired_on < ?)` 하고 바뀐 줄이 1이면 `{ first: true }`, 0이면 `{ first: false }` (동시에 두 번 와도 한 번만 참).
  - **`<` 로 견줍니다(`<>` 가 아님)**: 날짜는 `YYYY-MM-DD` 글자라 SQLite·Postgres 모두 글자 순서 = 날짜 순서입니다. 같은 날은 거짓, 다음 날은 참이라 요구와 같고, 더 **옛 날짜**(늦게 도착한 요청·기기 시계 차이)가 이미 적힌 새 날짜를 덮어 그날 서버 기록이 사라지는 일을 막습니다(옛 날짜는 `first: false`, `fired_on` 그대로).
  - Kysely: `.updateTable("price_alerts").set({ fired_on: date, fired_at: at, fired_value: value }).where("id", "=", id).where((eb) => eb.or([eb("fired_on", "is", null), eb("fired_on", "<", date)])).executeTakeFirst()` → `Number(r.numUpdatedRows) === 1`(bigint — `stockService.ts:509` 의 `Number(r.numDeletedRows)` 처럼).
- **`fired_value`(= 앱이 보내는 `value`)**: 울린 순간 조건을 판정한 값. 3-30 이 이 칸을 이어 씁니다.

  | kind | `value` | 예 |
  |---|---|---|
  | `priceAbove`·`priceBelow` | `quote.price` (종목 통화) | `88700`, `179.95` |
  | `rateUp`·`rateDown` | `quote.changeRate` (부호 그대로) | `8.97`, `-5.04` |
  | `volume` | 서버가 준 `ratio` (반올림한 값 그대로) | `3.29` |
- **`at`**: 울린 때 `new Date(nowMs).toISOString()`. 화면(`오늘 09:41 울림`)은 이 값의 서울 `HH:MM` 입니다.
- **기기 기록 (서버에 못 보냈을 때)**: AsyncStorage `priceAlerts.fired.v1` = `{ "<id>": "<date>" }`(조건마다 마지막 날짜 하나). 울리기 **전에** 메모리와 이 기록을 먼저 적습니다. 읽기·쓰기는 모두 try/catch(읽기 실패는 빈 기록으로 봄).
- **이번 실행 메모리**: 제공자 **인스턴스**의 `useRef<Set<string>>`(`"<id>|<date>"`). 모듈 전역에 두지 않습니다 — 모듈 전역이면 7장의 '제공자를 다시 그림(재시작 흉내)' 테스트가 서버·기기 기록이 아니라 메모리 때문에 통과해 버립니다. (`RUN_START` 는 모듈 전역 그대로.)
- **울려도 되는지**: `rule.firedOn !== date && 기기기록[id] !== date && 이번 실행 메모리에 (id,date) 없음`.
- 울린 뒤 조건 목록 캐시의 그 줄을 `firedOn = date`, `firedAt = 지금` 으로 바로 고칩니다(시트·설정 칸이 '오늘 울림'을 보이게). 서버 응답은 기다리지 않습니다(3초 예산 밖).
- 알려진 한계: 두 기기가 같은 서버를 쓰면 둘 다 울릴 수 있습니다(서버 기록은 먼저 온 쪽). 앱을 지우고 다시 깔았는데 그때 서버에 못 보낸 기록이 있으면 그날 한 번 더 울릴 수 있습니다.

### 3.5 울릴 때 (화면 위 알림 · 진동 · 화면 읽기 · 알림 목록)

한 번의 확인에서 울리는 조건들을 모은 뒤 이 차례로: 기록(3.4) → 카드 상태에 더함 → `haptic("alert")` **한 번** → 화면 읽기 알림 **한 번** → 조건마다 `notifyPriceAlert` → 조건마다 `api.priceAlertFired(...).catch(() => undefined)` → 목록 캐시 고침.

- **화면 위 알림 카드** (`PriceAlertBanner`): 모든 화면 위(루트 레이아웃에서 `<Navigator />` 뒤 형제로 제공자가 그림), 위쪽 안전 영역 + `space.sm` 아래, 좌우 `space.md`, 최대 폭 `priceAlert.bannerMaxW`(520, 펼친 화면은 가운데). 바탕 `t.surfaceAlt`, 테두리 `t.lineStrong`, 모서리 `radius.lg`. 머리 줄 = 종 아이콘(Ionicons `notifications`, `t.gold`) + `가격 알림`(font.small, `t.muted`) + 오른쪽 닫기(Ionicons `close`, 44dp). 알림 줄 = 제목(font.body 굵게, `t.ink`, 최대 2줄) + 본문(font.small, `t.sub`, 최대 2줄). 글자 확대 상한 `fontCap.row`.
  - 한 번에 여러 조건이 울리면 한 카드에 최신부터 **3줄**(`priceAlert.bannerRows`), 넘치면 맨 아래 `외 N건`. 카드가 떠 있는 동안 새로 울리면 맨 위에 더합니다.
  - 알림 줄을 누르면 `router.push("/stocks/<code>")` 하고 카드를 닫습니다. 닫기는 모두 닫음.
  - **저절로 닫힘**: 마지막으로 줄이 더해진 뒤 `priceAlert.bannerHideMs`(10초). 화면 읽기가 켜져 있으면(`AccessibilityInfo.isScreenReaderEnabled()`) 저절로 닫지 않습니다.
  - 화면 읽기: 한 번의 확인에서 울린 것들을 **한 번만** `AccessibilityInfo.announceForAccessibility(announceText(hits))` 로 읽습니다(4.2 '화면 읽기 문장'). 카드에는 `accessibilityLiveRegion` 을 **두지 않습니다** — 둘을 함께 쓰면 TalkBack 이 같은 알림을 두 번 읽을 수 있습니다(카드가 새로 그려질 때 한 번, 알림 말 한 번). 카드의 줄·닫기 버튼 이름표는 그대로 둡니다(손가락으로 짚으면 읽음).
  - 알려진 한계: 알림 시트(RN `Modal`)가 열려 있으면 카드는 시트 뒤에 그려져 시트를 닫은 뒤 보입니다(진동·화면 읽기는 바로).
- **진동**: `haptic("alert")` — 새 종류(5장 앱 8). 한 번의 확인에서 여러 조건이 울려도 **한 번**.
- **알림 목록 한 줄**: 알림 권한이 **이미** 있을 때만(`getPermissionsAsync()` 가 granted — 이 기능은 권한을 묻지 않음) 조건마다 로컬 알림 하나를 `prices` 채널로 올립니다. 본문은 `ruleLabel(rule) + " · " + hitBody(hit)` — 카드 본문과 같이 기준 표시(` · NXT 포함` 등, 3.6)까지 붙습니다(4.2). 앱이 앞에 있을 때만 올리므로(3.2) 핸들러가 소리·팝업을 끕니다(5장 앱 9 `presentationFor`) — expo-notifications 57.0.20 안드로이드는 `shouldPlaySound: false` 면 `setSilent(true)`(채널 소리·진동과 상관없이 조용히)로 올립니다. 누르면 그 종목 상세.
- 모든 숫자는 캐시의 시세·서버 응답 값을 모양만 바꿔 씁니다(새로 계산하지 않음, 배율 표기만 3.6).

### 3.6 숫자 모양

- 가격: `formatPrice(v, currency)`(`app/src/lib/format.ts:43` — `88,600원`, `$12.00`, 1달러 미만도 `$0.46`). 시세 머리와 같은 두 자리.
- 등락률: `formatPct(v)`(`format.ts:90` — `+5.00%`, `-5.00%`). 조건 글의 하락 쪽은 `formatPct(-value)`.
- 시각: 시세 `asOf`(거래량은 서버 `asOf`)의 **서울 시각** `HH:MM`. 화면 읽기는 `speakClock`(`app/src/lib/a11y.ts`, 브리핑 2차 2+3 — `"10:12"` → `10시 12분`, `"09:00"` → `9시`)을 불러 씁니다. `main` 에 없으면 같은 결과의 작은 함수를 `priceAlerts.ts` 안에 둡니다(a11y.ts 는 고치지 않음).
- 거래량: `formatVolume(n)`(`format.ts:119` — `312만`) + `주`. 배율은 **내림** 소수 한 자리: `(Math.floor(Math.round(ratio * 100) / 10) / 10).toFixed(1)` (`3.29` → `3.2배`, `3` → `3.0배`) — 실제보다 크게 보이지 않게, 부동소수 꼬리 없이.
- 기준 표시(`quote.priceBasis`, 서버가 주는 값 — `toss.ts:263, :560-576`, `tossOpenApi.ts:659`, `naver.ts:121`): `KRX+NXT 통합` → ` · NXT 포함`, `주간거래` → ` · 주간거래`, `최근 체결(시간외 포함)` → ` · 시간외 포함`, 그 밖(`KRX 정규장`·`정규장`·없음) → 붙이지 않음.

### 3.7 시트에 미리 채우는 값 (터치 ② 의 줄들)

`p = quote.price`, 통화 `cur`.
- **보기 좋은 단위** `niceStep(p, cur)`: 원 — `p < 1,000` → 1, `< 10,000` → 10, `< 100,000` → 100, `< 1,000,000` → 1,000, 그 밖 10,000. 달러 — `p < 10` → 0.01, 그 밖 0.1. (거래소 호가 단위를 흉내 내지 않습니다 — 알림 값일 뿐이라 호가 표를 새로 넣지 않음.)
- **정수로 계산** (부동소수 때문에 `$3.00 × 1.05` 가 `$3.16` 이 되지 않게): 원은 원 단위, 달러는 **만분의 1 달러** 정수 `u = Math.round(p * 10_000)`, 단위도 같은 정수 `s`(0.01 → 100, 0.1 → 1,000). 가격 위 = `Math.ceil((u * 105) / (100 * s)) * s`, 가격 아래 = `Math.floor((u * 95) / (100 * s)) * s`, 달러는 마지막에 `/ 10_000`. 예:
  - 84,300원 → `88,600원 이상` · `80,000원 이하`, 9,870원 → `10,370원 이상` · `9,370원 이하`, 100원 → `105원 이상` · `95원 이하`
  - `$11.34` → `$12.00 이상` · `$10.70 이하`, `$0.4321` → `$0.46 이상` · `$0.41 이하`, **`$3.00` → `$3.15 이상` · `$2.85 이하`**, **`$0.60` → `$0.63 이상` · `$0.57 이하`**
- 가격 줄 둘째 글: `지금보다 ${formatPct((v / p - 1) * 100)}` (예 `지금보다 +5.10%`, `지금보다 -5.10%`).
- 등락률 위: 단계 `[5, 10, 15, 20, 30]` 중 `max(changeRate, 0)` 보다 **큰** 첫 값. 등락률 아래: 같은 단계 중 `max(-changeRate, 0)` 보다 큰 첫 값. 없으면(30% 넘게 움직임) 그 줄 없음. 예: +3.56% → `+5.00% 이상`·`-5.00% 이하`, +6.2% → `+10.00% 이상`·`-5.00% 이하`, +5% → `+10.00% 이상`. 둘째 글 `지금 전일 대비 +3.56%`.
- 거래량: `3` 배. 둘째 글은 4.2.
- 시세가 없으면(`quote` null) 가격·등락률 줄 대신 안내 한 줄(4.2), 거래량 줄만.
- 줄 차례: 가격 위 · 가격 아래 · 등락률 위 · 등락률 아래 · 거래량. 처음에는 아무 줄도 고르지 않은 상태([알림 저장] 꺼짐).
- 값 조절(고른 줄 아래에 펼침):
  - 가격: [−] [입력칸] [+]. 한 번에 `max(niceStep, p × 0.01 을 niceStep 으로 반올림)`(84,300원 → 800원, `$11.34` → `$0.10`), 같은 정수 단위로 더하고 뺌. 입력칸은 숫자 자판(원 `number-pad`, 달러 `decimal-pad`).
  - 등락률: [−] [입력칸] [+], 한 번에 1(%p), 1~30.
  - 거래량: 칩 [2배] [3배] [5배] [10배].
- 검사 `validateDraft(draft, rules)` (4.2 오류 글, 하나라도 걸리면 [알림 저장] 꺼짐): 원은 1 이상 1억 이하 정수, 달러는 0.01 이상 100만 이하·소수 둘째 자리까지, 등락률 1~30·소수 둘째 자리까지, 거래량 {2,3,5,10}, **이미 있는 조건과 같은 (kind·value)** 면 `같은 알림이 이미 있습니다`, 그 종목 5개면 `한 종목에 알림은 5개까지입니다`. 서버도 같은 규칙·같은 식으로 검사합니다(5장 서버 6 `checkValue`, 4.3).
- **'소수 둘째 자리까지'의 식을 고정합니다** — 앱·서버 모두 이 식 하나만 씁니다:
  ```ts
  /** 소수 둘째 자리까지인 수인지 (센트·등락률). v*100 이 정수인지로 보면 0.29*100 = 28.999999999999996 처럼 부동소수 꼬리 때문에 정상 값을 거절한다 */
  export function hasCents(v: number): boolean {
    return Number.isFinite(v) && Math.round(v * 100) / 100 === v;
  }
  ```
  원은 `Number.isInteger(v)`. **`Number.isInteger(v * 100)` 은 쓰지 않습니다**: 노드에서 `0.29*100 = 28.999999999999996`, `0.57*100 = 56.99999999999999`, `1.15*100 = 114.99999999999999`, `4.35*100 = 434.99999999999994`, `1.1*100 = 110.00000000000001` 이라 3.7 이 미리 채운 `$0.57 이하`(from `$0.60`)·`$0.29` 와 등락률 `1.15`·`1.1` 을 '값 오류'로 막고, 서버도 400 을 줍니다(미국 종목에서 3번 터치 저장이 막힘). `hasCents` 는 `12.1`·`0.29`·`0.57`·`4.35`·`1.15`·`1.1` 은 참, `12.101`·`12.345`·`1.155`·`0.001` 은 거짓입니다(이 PC 의 노드로 확인). `stepDraft` 가 만든 값(`만분의 1 달러 정수 / 10_000`)도 `hasCents` 가 참입니다.
  - 검사 차례와 글: 범위 먼저(`1원 이상 1억 원 이하로 넣어 주세요` · `$0.01 이상 $1,000,000 이하로 넣어 주세요` · `1~30 사이로 넣어 주세요`), 그다음 자리(`소수 둘째 자리까지 넣어 주세요` — 달러·등락률), 원이 정수가 아니면 범위 글과 같은 `1원 이상 1억 원 이하로 넣어 주세요`(원 입력칸은 `number-pad` 라 보통은 생기지 않음).

## 6. 경계와 주의

1. **앱을 켰을 때 이미 조건에 맞음** → 새로 받은 목록으로 첫 확인에서, 그날 아직 안 울렸으면 한 번(3.2). 기기에 저장해 둔 옛 목록으로는 울리지 않음.
2. **같은 날 넘었다 내려왔다 다시 넘음** → 한 번. 다음 거래일에 다시 맞으면 또 한 번.
3. **거래일 경계**: 한국 07:59 까지의 시세·체결은 전날 거래일(08:00 NXT 프리부터 새 날), 미국은 뉴욕 20:00(한국 10:00·서머타임 중에는 09:00)부터 다음 거래일(주간거래). 어제 시세가 남은 아침에 울리지 않음.
4. **동시호가·장 마감·휴장·거래정지·대상 아님**: `session.open` 거짓 또는 `eligible` 거짓이면 가격·등락률로 울리지 않음. NXT 대상 종목은 NXT 프리(08:00~08:50)·애프터(15:40~20:00)에도 울림(기준 표시 `NXT 포함`). 미국 주간거래 대상도 그 시간에 울림(`주간거래`).
5. **시세 지연(`stale`)** 이면 울리지 않음. 체결은 `stale` 표시를 바꾸지 않으므로(`liveTick.ts` `applyTick`) 서버가 지연을 알린 종목은 다음 정상 시세까지 체결이 와도 울리지 않음(허용 — 조심하는 쪽).
6. **거래량**: 첫 30분 `early`, 정규장 밖·휴장 `closed`, 수능일(10:00 개장)·새해 첫 거래일·미국 조기 폐장은 그날 개장 기준으로 경과 시간을 맞춤, 서머타임이 바뀐 주도 뉴욕 현지 시각으로 맞춤. 마감 단일가 봉의 치우침·장중 거래정지 날의 적은 거래량은 평균에 그대로 들어감(알려진 한계). 30분봉 450개 한도로 `days` 가 20보다 작을 수 있음(3.3).
7. **웹소켓 끊김**: 활성 가격·등락률 조건이 있으면 `ListWatch` 가 늘 주기 요청을 하므로(잔고 탭이 가려져 있어도, `WidgetBridge` 등이 같은 키를 `enabled: false` 로 보고 있어도 — 3.2) 끊긴 동안 `useLivePoll` 주기(3~4초, 장이 닫히면 1분·pollSaver 5분)로 받은 목록으로 확인. 잔고 탭이 함께 보고 있으면 같은 주기라 한 요청으로 합쳐짐. 폴링도 실패하면 확인하지 않음(울리지 않음).
8. **앱이 뒤로 감·화면 꺼짐**: 소켓을 끊고 react-query 주기 갱신도 멈춤(`_layout.tsx:130-135` `focusManager`), 엔진도 `AppState` 가 `active` 가 아니면 확인하지 않음 → 뒤에서 알림을 올리지 않음. **돌아온 순간에는 확인하지 않고**(뒤에 있던 동안 캐시에 들어온 값으로 몇 시간 늦게 울리지 않게 — 3.2 `activeSince`), 돌아온 뒤 새로 받은 값(소켓 스냅샷·주기 요청)으로 확인 → 그사이 맞았고 그날 안 울렸으면 한 번. (앱이 꺼져 있어도 울리는 것은 3-30.)
9. **미국 종목 원화 보기**: 조건·알림 글은 달러(3.1).
10. **등록에서 뺀 종목(쉬는 중)**: 조건은 남고 **어떤 길로도** 확인하지 않음(3.1 `activeRules`). 발견 탭·검색에서 그 종목 상세를 열어 `[apiUrl, "stock", code]` 가 3초마다 받아져도(미등록 상세는 스트림 주기가 아님 — `hooks.ts:143-155`), 서버가 아직 잊지 않은 삭제 종목 체결이 와도 울리지 않음. 거래량 조건은 `/volume` 요청 코드에 넣지 않음. 시트는 열 수 없음(버튼이 등록 종목에만). 삭제 뒤 잔고 목록을 다시 받으면 코드 모음이 바뀌어 조건 목록을 다시 받으므로 시트·설정 칸 글이 `등록 종목이 아니라 확인하지 않음` 으로 바뀜(지울 수 있음). 다시 등록하면 같은 길로 다시 활성.
11. **여러 조건이 한꺼번에**: 카드 한 장에 3줄 + `외 N건`, 진동 한 번, 알림 목록은 조건마다 한 줄(소리 없음).
12. **화면 읽기 켜짐**: 카드가 저절로 닫히지 않음. 알릴 때 문장을 읽음.
13. **알림 권한 없음**: 알림 목록 없이 카드·진동만. 이 기능은 권한을 묻지 않음(첫 실행 안내·설정의 알림 켜기가 묻는 곳).
14. **조용한 시간(기본 22~07시)**: 사용자가 앱을 보고 있는 중이라 카드·진동은 그대로, 알림 목록 줄은 원래 소리가 없음. 브리핑 알림의 조용한 시간 규칙은 바꾸지 않음.
15. **플래그를 껐다 켬**: 조건은 서버에 그대로(끄면 숨길 뿐). 켜는 순간 3.4 규칙으로 이어짐.
16. **서버 주소를 바꿈**: 조건은 서버마다(캐시 키에 `apiUrl`). 기기 기록은 id 로 적으므로 다른 서버의 같은 id 가 그날 울리지 않을 수 있음(드묾, 허용).
17. **폭·글자**: 475·411 × 글자 100·130·150%(막대 글자 상한 `fontCap.chrome`)에서 막대 글자가 잘리지 않게 `alertBarLabel` 로 아이콘만으로 줄임. 관심 종목 `동기화 제외`(가장 긴 글)도 확인. 시트는 글자 200% 에서 스크롤로 모두 보이고 [알림 저장]은 늘 보임.
18. **다크·라이트**: 토큰만(`t.surface`·`t.surfaceAlt`·`t.lineStrong`·`t.gold`·`t.ink`·`t.sub`·`t.muted`·`t.warn`·`t.accent`·`t.accentInk`·`t.scrim`).
19. **새 요청 수(켜졌을 때)**: 조건 목록 30초 캐시(앱으로 돌아올 때 30초 넘었으면 한 번, 등록 종목이 바뀌면 한 번, 실패 중이면 1분마다), 활성 거래량 조건이 있을 때만 30초마다 1번(모두 정규장 밖이면 5분마다, 서버는 봉을 받지 않음), 활성 가격 조건이 있으면 다른 탭에서도 잔고 목록을 받음(스트림 중엔 보정 30초, 끊기면 3~4초 — 잔고 탭이 보고 있으면 같은 주기라 한 요청으로 합쳐져 추가 0). 꺼지면 0.
20. **같은 조건 두 번 저장**: 시트가 먼저 막고(`같은 알림이 이미 있습니다`), 서버도 409(동시에 두 번 와도 `onConflict … doNothing` 으로 하나만 들어가고 나머지는 409).
21. **미국 종목의 '하루'**: 날짜 열쇠는 그 종목 거래일이라 미국은 뉴욕 20:00(한국 10:00·서머타임 중에는 09:00)에 날이 바뀝니다. 그래서 같은 조건이 **한국 시간 같은 아침에 두 번** 울릴 수 있습니다(뉴욕 애프터마켓 D 에서 한 번, 20:00 뒤 주간거래 D+1 에서 한 번). 정의대로의 동작(거래일마다 한 번)이며, 사용자에게는 '하루 중복'처럼 보일 수 있어 8.3 에 적고 Claude 가 사용자 보고에 넣습니다.
22. **NXT 대상이 아닌 한국 종목의 마감 단일가**: 15:20~15:30 은 동시호가(`session.open` 거짓)이고 15:30 뒤는 장 마감이라, 마감 단일가 체결로 조건에 닿아도 **그날은 울리지 않습니다**(다음 거래일에 조건이 여전히 맞으면 그날 첫 확인에서 한 번). NXT 대상 종목은 15:40 애프터 체결부터 다시 확인합니다. 알려진 한계(8.3).
23. **세션 경계 뒤 다시 받기가 늦음**: `session.until` 이 지난 `session` 은 믿지 않아 울리지 않음(3.2 4번). `useLivePoll` 이 가장 가까운 세션 경계 뒤 한 번 더 받으므로(`hooks.ts:131, :148` `capToBoundary`) 보통은 곧 새 `session` 이 옴.
24. **조건 목록 받기 실패**: 404(예전 서버)면 조건 없음·다시 묻지 않음. 그 밖의 실패는 받은 적 있는 목록이 있으면 그것으로 계속, 한 번도 못 받았으면 엔진을 시작하지 않고(ListWatch·VolumeWatch 도 없음) 1분마다·앱으로 돌아올 때 다시 받음 → 받는 순간 엔진이 시작하고 '지금 캐시로 한 번 확인'.
25. **거래량 응답이 느림**: 서버 시간 예산 35초·앱 시간 제한 45초(3.3). 예산을 넘은 종목은 그 회차에 `unavailable`(울리지 않음), 다음 회차에 다시.
26. **저장 직후 이미 맞는 조건**: 체결이 뜸한 종목이어도 저장 뒤 조건 목록을 다시 받는 순간 지금 캐시로 확인해 한 번 울림(3.2). 그 캐시 값이 앱이 뒤에 있던 동안 받은 것이면 새 값이 올 때까지 기다림.

- [ ] 종목 상세에서 **3번 터치**로 조건 저장(아래 막대 [알림] → 줄 → [알림 저장], 테스트가 저장 본문을 확인). 미국 종목도(`$12.10`·`$0.29` 저장 켜짐 — `hasCents`, 앱·서버 테스트).
