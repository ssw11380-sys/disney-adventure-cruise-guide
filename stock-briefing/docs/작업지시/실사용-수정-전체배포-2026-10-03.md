# 실사용 점검 수정본 전체 배포

2026-10-03 사용자가 "전부 배포해줘"라고 명시적으로 요청했다. 기존 문서의 Claude 전용 배포 규칙 및 앞선 작업의 배포 제외 범위는 이번 승인 범위에 한해 대체한다. Codex가 검증된 수정본을 main에 통합하고 서버·기존 Android 앱 채널에 배포한다.

## 배포 대상과 보존 기준

- 수정 기준: `28806e16c165d0afbd2ed8f771ace38a03219a5a`. 서버 1,881개·앱 3,489개 검사와 Android export 통과.
- 현재 운영 main/서버: `67c5bd6f11bdf3fd96dbf233c6dfe80dec4e688f`.
- 현재 게시 앱: `e29d38879564b878d6c10b661104bf28e94abcf0`, preview / Android / runtime 1.5.0. 그룹 `862ca780-0895-4889-8098-50a1bea7bf12`.
- 최신 main에서 통합 브랜치를 만들고 두 기준 사이 실제 파일 차이를 반영한다. 제품 코드와 검사는 수정 기준과 정확히 일치하는지 확인한다. 기존 main에 없지만 이미 게시된 앱의 로그인 준비 코드도 보존하여 앞으로 main에서 앱을 게시할 때 되돌아가지 않게 한다.
- 별도 개발 중인 서버 계정 기능·마이그레이션·토스 키 기능은 가져오지 않는다. DB 구조·기존 자료·모델 등급·프롬프트·자료 범위·출력 한도·의존성·네이티브 설정을 변경하지 않는다.

## 배포와 확인 순서

1. 운영 버전·EAS 채널·미커밋 변경·진행 보고서 상태를 읽기 전용으로 확인한다.
2. 통합 PR의 전체 CI 통과와 main의 동시 변경 여부를 확인한 뒤 병합한다. 하나의 담당자가 배포한다.
3. Railway 배포의 소스 커밋·성공 상태와 운영 health/API 상태를 함께 확인한다. health 자체는 소스 커밋을 반환하지 않는다.
4. EAS의 기존 preview 환경을 사용해 Android/runtime 1.5.0 OTA를 게시한다. 새 APK, 다른 플랫폼/채널, 서버 환경값 변경은 포함하지 않는다.
5. 실제 업데이트 제공 manifest의 ID와 runtime, 내려받는 번들 확인 결과를 기록한다. 사용자의 폰 적용은 별도로 구분한다.

인증값은 기존 배포 환경에서 메모리로만 사용하고 출력하지 않는다. 유료 모델 재생성·실거래·보유 데이터 수정으로 배포를 확인하지 않는다. 실패하면 현재 상태와 원인을 먼저 기록하고, 확인되지 않은 성공을 보고하지 않는다. 되돌릴 기준과 배포 결과는 별도 배포 Markdown에 남긴다.
