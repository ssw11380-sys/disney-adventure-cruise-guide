# 보고서 속도 개선 — 품질 유지

## 사용자 요청과 범위

2026-10-02 사용자 요청: “변경해서 개선시켜줘, 대신 결과값의 퀄리티가 낮아지면 안되는거야”. 이 요청은 이전의 확인 전용 지시를 이번 개선에 한해 바꾼다. 기준 커밋은 `c03a187ddc667a8b44c2112a3d28ebbba3378b26`이며 `codex/report-latency-quality` 별도 작업 폴더에서 구현한다.

실제 병목인 종목별 순차 생성과, 생성 중인지 알 수 없는 화면 및 앱의 대기 시간 초과 뒤 결과를 못 받는 문제를 고친다. 모델 변경은 범위에 없다.

후속 배포 요청: 사용자가 배포 여부를 확인한 뒤 “아 이번에는 우리가 직접 수정해버리자”라고 요청했다. 이번 작업에 한해 Codex가 PR·CI 확인·main 병합·Railway 배포 확인·Expo OTA를 담당한다. 이 요청은 기존 AGENTS.md의 Claude 전담 배포 규칙과 아래 Claude 확인 항목의 담당자를 이번 작업에 한해 바꾼다. 다른 작업·배포 설정·의존성·네이티브 변경은 포함하지 않는다. 실제 app.json과 release.json은 1.5.0이며 runtimeVersion은 appVersion 정책이다. 기존 설치 앱의 preview 채널·preview 환경·Android OTA로 진행하고 서버가 먼저 반영된 것을 확인한다.

후속 강조: “속도가 느려지면 안 되는 거야, 속도가 빨라야 해”. 정상 생성 경로의 추가 대기를 없애고, 실제 완료 시간 기준으로 검증한다. 단순히 기다릴 수 있는 시간을 늘리거나 진행 표시만 더한 것을 속도 개선으로 판정하지 않는다.

## 품질을 유지하는 조건

- 모델·프롬프트 파일·입력 자료 선택·분석 노력 수준·출력 토큰 한도·검증기를 바꾸지 않는다.
- 종목마다 기존처럼 자료 수집 → 상세 분석 → 그 상세를 사용한 요약을 실행한다. 호출을 합치거나 요약을 생략하지 않는다.
- 자료를 빨리 포기하거나 더 짧은 제한 시간으로 분석을 끊어 속도를 높이지 않는다.
- 기존 자료 누락 표시, 정상 보고서 보존, 알림 묶음, 휴장·중복 실행 방지 정책을 유지한다.
- 가짜 모델과 고정 자료에서 순차/동시 실행의 종목별 모델 입력·옵션·본문·요약이 같은지 확인한다. 실제 생성형 모델의 문장 동일성이나 운영 속도 개선율을 가짜 테스트로 보장하지 않는다.

## 구현

1. `briefingParallel`: 최대 두 종목을 동시에 준비한다. 각 종목의 상세→요약 순서 및 등록 순서대로 저장·결과·리스너 전달을 유지한다. 예외가 발생해도 시작한 작업이 끝나기 전에는 실행 중 표시를 내리거나 완료 알림을 보내지 않는다. 플래그를 끄면 기존 순차 실행을 유지한다.
2. `analysisWaitRecovery`: 분석 생성 요청을 즉시 한 번 시작하고, 이전 내용을 읽는 상태 조회는 보조로 병행한다. 상태 조회가 늦거나 실패해도 정상 보고서 반환을 지연시키지 않는다. 고유 요청 ID를 생성 요청과 읽기 전용 `GET /api/stocks/:code/analysis/:kind/state`에 함께 보내 해당 요청이 완료한 정확한 결과만 회수한다. 로컬 캐시와 서버의 옛 ID 차이로 새 결과를 판정하지 않는다. 화면은 갱신 중 기존 내용을 유지하며, 확인 불가 상태를 성공으로 표시하지 않는다. 플래그를 끄면 기존 동작, 신규 경로 404.
   - 버그 수정(플래그 없음): 생성 시각이 같은 분석 여러 건은 `id DESC`를 두 번째 정렬로 적용해 마지막 저장 결과를 선택한다. 같은 시각의 옛 ID를 계속 회수하는 오류를 막는 수정으로, 기능을 꺼도 최신 결과 선택에는 적용한다.
3. `briefingLiveProgress`: 기존 상태 응답에 현재 실행 `activeRun`을 추가해 예약 전 수동 실행·일부 종목 실행까지 표시한다. 준비 중·N개 중 M개 처리·마무리 중을 구별하며 실패/건너뜀을 성공 건수로 표현하지 않는다. 기존 20분 지연 경고 판정은 유지한다. 플래그를 끄면 기존 응답·안내·조회 간격을 유지한다.

## AGENTS.md와의 관계

사용자의 이번 명시적 구현 요청을 새 작업지시로 삼는다. 한국어, 비밀값 보호, 기능 플래그, 기존 스냅숏 유지, 의존성·네이티브·배포 변경 금지는 그대로 따른다. 기존 기능 테스트를 약화하지 않는다. 순차 호출 순서를 검증하는 기존 테스트는 준비 단계에서 `briefingParallel: false`만 추가하여 기존 기대값을 보존할 수 있다. 새 플래그 전체 목록 기대값은 세 키만 추가한다.

후속 수정은 앞 구현의 분석 복구 테스트를 요청 ID 계약에 맞춰 갱신한다. 기존 180초 시간 초과·3회 오류·10분 조회 한도·이전 본문 보존·플래그 전환·서버 교체·읽기 확인의 생성 0회 검증은 유지한다. 별도로 정상 생성 소요 시간이 상태 조회 지연과 합산되지 않는지, 늦은 보조 응답이 새 본문을 덮지 않는지, 다른 요청의 결과를 성공으로 오인하지 않는지 확인한다.
