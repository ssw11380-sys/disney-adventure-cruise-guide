     ```ts
     /** 계좌 합계(잔고 summarize·위젯 totals)에 들어간 보유 종목: isHolding 이고 시세·평가가 있고, 달러 종목은 환율(fxOf(s) ?? sharedFx(목록))이 있을 때만 */
     export function countedHoldings(stocks: readonly RegisteredWithQuote[]): RegisteredWithQuote[]
     ```
     - `isHolding`·`fxOf`·`sharedFx` 는 `lib/portfolio.ts`(:32, :12, :20)의 것을 씁니다(`sharedFx` 는 readonly 배열을 받지 않으므로 `[...stocks]` 로 넘김). `summarize`(:105-157)의 `countable` + `USD && !fx → noFx` 와 같은 규칙입니다.
     - 공용 환율이 목록의 어느 달러 시세에서든 나오므로, 환율 없는 달러 종목은 **늘 모두 함께** 빠집니다. 이때 `summarize(...).krw === null` 이고 화면 총액은 `총 평가금액 (원화 종목)`(= `account.total === null`)이라 **미국 줄 전체가 합계 밖**입니다 — 이 함수는 그 경우 달러 종목을 하나도 돌려주지 않아 화면과 맞습니다(테스트로 묶음, 1.7).
   - `hmLabel(ms: number, now: number): string` — 한국 시간. 오늘(한국 날짜)이면 `14:03`, 아니면 `9/26 05:00`.
   - `marketBasis(stocks: readonly RegisteredWithQuote[]): MarketBasis[]`
     ```ts
     export interface MarketBasis { market: "KR" | "US"; count: number; tags: { tag: BasisTag | null; count: number }[]; from: number | null; to: number | null; stale: string[] }
     ```
     - 대상은 `countedHoldings(stocks)`. 시장은 `quote.currency === "USD"` 면 `US`, 아니면 `KR`(`summarize` 의 통화 구분과 같음). 한국 → 미국 순서, 종목이 없는 시장은 뺌.
     - `tags`: 기준별 종목 수. 많은 순, 같으면 `NXT`·`주간거래`·`시간외`·`정규장`·`null` 순.
     - `from`·`to`: 그 시장 종목 `quote.asOf` 의 가장 이른·늦은 시각(ms). 읽을 수 있는 것이 없으면 `null`.
     - `stale`: `quote.stale` 인 종목 이름.
   - `basisLine(m: MarketBasis, now: number): string` — `국내 3종목 · NXT 포함 · 14:02~14:03`, `미국 14종목 · 주간거래 12 · 정규장 2 · 9/26 05:00~14:03`.
     - 이름: `KR` → `국내`, `US` → `미국`. 기준이 하나면 그 말만, 여럿이면 `말 수`(수 앞 한 칸)를 ` · ` 로. `null` 기준의 말은 `기준 모름`.
     - 시각: `hmLabel(from)`~`hmLabel(to)`, 둘이 같은 글이면 하나만, `from` 이 없으면 시각 부분을 뺌.
   - `diffPctText(abs: number): string` — `abs.toFixed(2)`. 그 글이 0.1 이하로 보이는데 `abs > WARN_PCT` 면(예: 0.104 → `0.10`) `abs.toFixed(3)`(`0.104`) — 0.1% 초과를 `0.10%` 로 보이지 않게.
   - `staleAfterMin(sync: ReconcileBadgeBody["sync"]): number` — 마지막 기록이 '오래됐다'고 볼 분:
     - 기대 간격 `gap` = `sync` 의 `lastRunAt`·`nextRunAt` 이 둘 다 읽히고 `nextRunAt > lastRunAt` 이면 `(nextRunAt − lastRunAt) / 60_000`(분, 지금 동기화 주기 — 장중 10·장 밖 60), 아니면 `sync?.idleIntervalMin ?? 60`.
     - 결과 = `gap + 10`.
     - `nextRunAt` 만 보지 않는 까닭: 동기화가 계속 실패해도 서버는 다음 실행 시각을 계속 앞으로 옮기므로, `nextRunAt` 만 보면 '오래됨'이 영영 오지 않습니다. 마지막 **기록** 시각에서 잽니다.
   - `reconcileBadge(body: ReconcileBadgeBody | null | undefined, now: number): Badge`
     ```ts
     export interface Badge { kind: "none" | "wait" | "old" | "qty" | "missing" | "over" | "ok"; text: string; tone: "ok" | "warn" | "muted"; speech: string }
     ```
     위에서부터 처음 맞는 줄(글·화면 읽기는 1.5-1 표 그대로):
     1. `body` 가 없음(받기 전·실패) 또는 `on` 거짓 또는 `status` 없음 → `none`
     2. `status.last` 없음 → `wait`
     3. `now − Date.parse(last.at) > staleAfterMin(body.sync)분` → `old`
     4. `last.qtyMismatch` 가 비어 있지 않음 → `qty`
     5. `last.missing > 0` → `missing`
     6. `Math.abs(last.diffPct) > WARN_PCT` → `over`
     7. 그 밖 → `ok`
     - 배지는 **마지막 기록 그대로**입니다. '3번 연속이면 경고'(3-13)는 서버 경고 규칙이라 배지에 쓰지 않습니다(연속 횟수는 창에만).
   - `basisRows(o): BasisRow[]` — 창의 줄. 부품이 아닌 값만 받습니다(`AccountBand.tsx` 의 `fxNote` 를 여기서 부르지 않음 — 그 파일은 RN 을 불러옴):
     ```ts
     export interface BasisRow { key: string; label: string; lines: string[]; warn?: boolean; muted?: number[] }
     export function basisRows(o: {
       stocks: readonly RegisteredWithQuote[];
       afterCost: boolean;
       fxNote: string | null;      // AccountBand 의 fxNote(data)
       excluded: string | null;    // AccountData.excluded
       reconcile: ReconcileBadgeBody | null | undefined;
       now: number;
     }): BasisRow[]
     ```
     줄과 조건은 1.5-2 표 그대로. `muted` = 흐린 글로 그릴 `lines` 의 번호.

### 1.5 문구 (그대로 씀)

**1) 점 옆 글 (`reconcileBadge`)** — 화면 읽기 이름표는 앞에 `숫자 기준 보기, ` 를 붙임. `{시각}` = 오늘이면 `speakClock(hmLabel(Date.parse(last.at), now))`(`14:00` → `14시`), 아니면 `formatDateKo(last.at, true)`. `{hm}` = `hmLabel(Date.parse(last.at), now)`. `{비교}` = `last.n` 이 있고 0 보다 크면 `같은 종목 {n}개 비교, `, 아니면 빈 글.

|---|---|---|---|
| `none` | `숫자 기준` | muted | `토스 대조 없음` |
| `wait` | `토스 대조 대기` | muted | `토스 대조 기록 없음` |

| `toss` | `토스 대조` | **`reconcile.on` 참 이고 `reconcile.status` 가 있음** | 아래 줄들 |

- `on` 참인데 `status` 가 `null`(서버가 대조 상태를 못 읽음)이면 배지는 `none` 이고 창에도 '토스 대조' 줄이 **없습니다**('아직 없음' 같은 틀린 안내를 하지 않게).

`토스 대조` 줄(있는 것만, 이 순서):
1. `reconcileLabel(status, (iso) => formatDateKo(iso, true), diffPctText)` — 설정 화면과 같은 글이되 %만 `diffPctText`(예 `차이 -1,234원 (-0.01%) · 9월 28일 (월) 14:00`, 0.104% 면 `(+0.104%)`). `status.last` 가 없으면 이 함수의 `아직 없음 (동기화 뒤 표시)`.
2. `last.n` 이 있고 0 보다 크면: `같은 종목 {n}개의 토스 평가금액(수수료·세금 차감)과 비교`
3. `status.streakOver >= 1` 이면: `0.1% 넘는 차이 {streakOver}회 연속`
4. `intraday` 가 있을 때만(서버가 못 셌으면 `null` → 이 줄 없음):
   - `n > 0`: `최근 7일 장중(정규장) {n}회 중 {withinPct}%가 0.1% 이내` — `withinPct` 는 서버가 소수 첫째 자리로 반올림한 숫자를 **그대로 글자로**(`75` → `75%`, `66.7` → `66.7%`, `toFixed` 를 쓰지 않음).
   - `n === 0`: `최근 7일 장중(정규장) 비교 기록 없음`
   - 둘 다 `skipped > 0` 이면 끝에 ` · 비교 못 함 {skipped}회`.
   - 예 `최근 7일 장중(정규장) 42회 중 97.6%가 0.1% 이내 · 비교 못 함 3회`
5. `sync` 가 있을 때만(흐린 글):
   - `sync.enabled` 참이고 `intervalMin > 0`: `토스 동기화 때마다 대조합니다 (장중 {intervalMin}분, 장 밖 {idleIntervalMin}분마다)`
   - 아니면(자동 동기화 꺼짐 — `TOSS_SYNC_MINUTES=0`·서버 스케줄러 꺼짐): `자동 동기화가 꺼져 있어 설정의 '지금 계좌 동기화' 때만 대조합니다`

끝 안내: `앱이 받은 시세로 계산한 숫자입니다 · 매매 권유가 아닙니다` (`BASIS_FOOT`).

### 1.6 경계

- **토스 연동 없음·`tossReconcile` 끔·예전 서버(404)·조회 실패·받기 전·대조 상태를 못 읽음(`status` null)**: `숫자 기준`(muted). 창에는 '토스 대조' 줄이 없고 나머지 줄은 그대로.
- **설정 '수수료·세금 차감 평가' 꺼짐**: 화면 합계는 비용 차감 전이지만, 토스 대조는 늘 비용 차감 평가끼리 비교합니다(`compareWithToss`). 배지는 그대로 두고 창의 '평가금액' 줄이 지금 설정을 밝힙니다.
- **대조가 보는 범위**: 토스 종목 중 '동기화 제외'가 아닌 것과 앱의 같은 종목만(`reconcileService.ts:5-13`). 그래서 `토스와 0.1% 이내` 는 **같은 종목끼리 앱 평가금액이 토스 평가금액과 0.1% 안에서 맞는다는 뜻**이고, 앱에만 있는 종목까지 맞췄다는 뜻이 아닙니다. 그래서 글을 '일치'가 아니라 '0.1% 이내'로 쓰고, 화면 읽기에 비교 종목 수, 창에 차이 금액과 `같은 종목 {n}개` 줄을 둡니다.
- **오래된 기록(`old`)**: 마지막 기록에서 `staleAfterMin` 분이 지나면 — 장중(동기화 10분)에는 20분, 장 밖(60분)·자동 동기화 꺼짐·주기를 모를 때는 70분. 동기화가 멈추거나 계속 실패하면 `토스 대조 12:50` 처럼 마지막 시각이 보입니다(실패해도 `nextRunAt` 은 앞으로 가므로 그것만 보지 않음).
- **0.1% 경계**: `Math.abs(diffPct) <= 0.1` 은 `ok`, 넘으면 `over`. `0.104` 는 점 옆 `토스와 차이 0.104%`, 창 첫 줄 `(+0.104%)`(둘 다 `diffPctText`).
- **1분 안에**: 서버가 기록 직후 알림 → 앱이 바로 다시 받음(연결돼 있으면 몇 초). 연결이 없으면 30초 주기 + 받는 시간. 잔고 탭이 가려져 있으면 받지 않고, 다시 보이면 받습니다(`refetchOnWindowFocus`, 구독). 앱이 꺼져 있을 때 바뀌는 일은 없습니다(범위 밖).
- **예전 앱 + 새 서버**: `reconcile` 알림을 무시하고 새 조회를 부르지 않음 — 지금 그대로. **새 앱 + 예전 서버**: 404 → `숫자 기준`.
- **보유 0(관심만)**: 계좌 패널·띠가 없으므로 점도 없음(지금 규칙).
- **합계에서 뺀 종목**: 시세 없음·평단(평가) 없음·환율을 몰라 원화 합계에서 빠진 달러 종목은 '시세' 줄 종목 수에 넣지 않고 '합계 제외' 줄로 알림. 환율 없는 달러 종목은 늘 함께 빠지므로(`countedHoldings`) 이때 '시세' 줄에 **미국 줄이 없고** 화면 총액도 `(원화 종목)` 입니다.
- **폭·글자**: 475·411·933·704 × 글자 100·130%에서 점 글은 한 줄(`numberOfLines 1`, 상한 `fontCap.row`), 총액 글자는 남은 폭에 맞춰 줄어듭니다. 넓은 한 줄 띠가 좁으면(`rates` 거짓) 점만. 점 칸은 늘 44×44 이고 '비중' 버튼과 누르는 영역이 겹치지 않습니다(좌우 `hitSlop` 없음). 창은 글자 130%에서 줄이 넘치면 창 안에서 스크롤.
- **다크·라이트**: 토큰만(`t.accent`·`t.warn`·`t.muted`·`t.surface`·`t.lineStrong`·`t.scrim`).
- **서버 부하**: 조회는 메모리 캐시(`history()`)만 읽음. 잔고 탭이 보이는 동안 30초마다 1번.
- 알림(브리핑·토스 경고) 수는 바뀌지 않습니다. `reconcile` 은 앱 화면용 실시간 메시지이지 휴대폰 알림이 아닙니다.

### 2.6 경계

- **위젯 폭**: 펼친 화면 넓은 잔고 위젯(약 780dp)은 붙고, 좁은 폭은 붙지 않는 것이 예상입니다(그림). 판단은 `textWidth` 어림값으로 하므로 **이 예상을 테스트 기대값으로 쓰지 않습니다**(2.7 — 기대값은 배치 함수와 같은 규칙으로 계산). 실제 폰 모습은 Claude 가 폰·웹으로 봅니다. 글자 130%·200% 에서는 더 적게 붙습니다.
- **기준을 모름**: 합계에 들어간 보유 종목 하나라도 `priceBasis` 가 없거나 모르는 값이면 붙이지 않음(예전 서버, 마지막 값으로 채운 옛 시세).
- **대상**: 잔고 화면과 같은 `countedHoldings` — 환율 없는 달러 종목·평단 없는 종목은 기준을 세지 않음(달러만 있는데 환율이 없으면 대상이 없어 글을 붙이지 않음 = 지금 그림).
- **앱이 그린 위젯과 위젯이 스스로 받은 그림이 같아야 함**: 앱은 잔고 시세의 `priceBasis`, 위젯은 응답의 `b` 를 같은 `basisShort` 로 — 번갈아 다른 글이 보이지 않게(서버 `b` 가 빠지면 두 쪽이 달라짐 — 테스트로 묶음).
- **예전 앱 + 새 서버**: `&ms=1` 이 없는 앱은 응답 그대로. `&ms=1` 인 지금 앱(이 OTA 전)은 `b`·`numberBasis` 를 모르는 칸이라 무시.
- **갱신 중·갱신 실패**: 기준 시각 자리가 다른 글이라 붙이지 않음.
- **브리핑 위젯**은 바꾸지 않음(요약 첫 줄은 2차 6 의 가격 줄이 이미 기준을 밝힘).
- **계좌 카드 시각**은 `createdAt`, 상세 '시세 기준' 줄은 `asOf`. 모델 설명(`accountBriefingLlm`, 기본 꺼짐)을 켠 날만 최대 1~2분 다를 수 있음(허용 — 2+3 의 기여 상위 묶음도 `createdAt`).
- **월요일 아침 브리핑 전**: 맨 위가 금요일 오후 브리핑이면 `16:05 기준` 이 보이고 날짜는 머리의 `9/25 오후` — 틀린 말 없음.
- **실패한 계좌 브리핑**: 시각·기준 줄 없음.
- **예전 계좌 브리핑**(`quoteBasis` 없음): 상세 줄 없음. 같은 날 다시 만든(수동 전체 실행) 브리핑부터 있음.
- 계좌 브리핑 요약·알림·사실·모델 입력은 켜도 꺼도 한 글자도 같음.
- 탭·상세 줄·카드의 배치(순서·줄 수)는 그대로 — 글만 더함. 넓은 창 2단 첫 화면 줄 수를 지키려고 계좌 줄에는 줄을 더하지 않고 둘째 줄 끝에 붙임(폭이 모자라면 그 줄 안에서 넘어감).
- 폭 411·475, 글자 130%에서 큰 카드의 `당일 손익 · 08:38 기준` 이 두 줄이 되더라도 잘리지 않음.

## 6. 왜 이렇게 했나 (결정)

- **점 + 짧은 글, 새 줄 0**: 로드맵 위험(화면이 복잡해짐)에 맞춰, 늘 보이는 것은 대조 결과 한 마디뿐이고 기준·시각의 자세한 뜻은 누르면 보이는 창에 모읍니다. 점만 두면 무엇인지 알기 어려워 글을 한 마디 붙이되, 좁은 한 줄 띠는 점만. 점이 작아도 누르는 칸은 44×44 로 두고, 옆 '비중' 버튼과 겹치지 않게 좌우로 넓히지 않습니다.
- **'토스와 일치'가 아니라 '토스와 0.1% 이내'**: 대조는 같은 종목끼리만, 차이 0.1% 이하(1억 기준 최대 10만 원)를 맞다고 봅니다. 앱에만 있는 종목까지 들어간 총액 바로 옆에 '일치'라고 쓰면 실제보다 강하게 읽혀, 숫자 투명성 목표에 맞게 기준을 글에 그대로 적었습니다. 화면 읽기에는 비교 종목 수를, 창에는 차이 금액을 둡니다.
- **배지는 마지막 기록 그대로**: 화면은 지금 상태를 보여 주는 곳이라 한 번의 0.1% 초과도 그대로 보입니다. 잘못 울리는 것을 막는 '3번 연속' 규칙은 서버 경고(3-13)에만 둡니다. 연속 횟수는 창에 적습니다.
- **'오래됨'은 지금 동기화 주기 + 10분**: 장중에 동기화가 멈췄는데 한 시간 넘게 '0.1% 이내'가 보이지 않게, 서버가 정한 다음 실행 간격(`nextRunAt − lastRunAt`)으로 잽니다. 실패해도 `nextRunAt` 은 앞으로 가므로 마지막 기록 시각에서 잽니다.
- **'장중' = 정규장 시간 기록, 비교 못 한 수도 함께**: 로드맵 기준 '장중 0.1% 이하 95%'를 장 밖 기록과 섞지 않고 재려고, 기록 시각이 한국·미국 정규장 시간인지를 휴장·조기 폐장·수능일 목록으로 판단합니다(`/health` 의 `week` 값은 그대로 둠). 시세 지연·수량 다름으로 비교하지 못한 기록은 분모에서 빠지므로, 비율이 부풀어 보이지 않게 그 수(`skipped`)를 창과 보고서에 같이 적습니다.
- **1분 안에 = 실시간 알림 + 30초 확인**: 대조 기록은 동기화(장중 10분마다) 때 생기므로, 기록 직후 알림으로 바로 바꾸고 연결이 끊겨도 30초 주기로 1분을 지킵니다. 30초 주기는 옵션 함수로 빼서 테스트로 묶습니다. `/health`(60초·무거움)는 주기를 바꾸지 않습니다.
- **기준을 세는 종목 = 바로 옆 합계에 들어간 종목**: 환율을 몰라 합계에서 빠진 달러 종목까지 세면 '미국 N종목'이라고 쓰는데 총액에는 없는 모순이 생깁니다. 앱 잔고·위젯은 `countedHoldings`, 서버 계좌 브리핑은 `computeAccount` 의 합계 종목으로 맞춥니다.
- **위젯은 자리가 남을 때만 글**: 위젯은 한 칸이라도 밀리면 칩·시각이 사라지므로, 기준 글 때문에 지금 보이는 것이 빠지는 일은 없게 했습니다. 안 붙는 크기는 누르면 잔고 탭(배지가 있음)이 열리지만, 그 창은 앱의 지금 기준이므로 '표시 100%' 판정에서 '두 번·다른 시점'으로 따로 적습니다.
- **브리핑 탭은 시각만**: 줄·카드 전체가 하나의 링크라 안에 누르는 점을 둘 수 없고, 2+3 이 정한 배치를 흔들지 않으려고 기존 줄 끝에 시각 글만 붙이고 기준은 상세 한 줄로 둡니다. 상세 줄은 자기 이름표로 한 번만 읽힙니다.
- **서버·앱 같은 기준 표**: 국내 `KRX+NXT 통합` → `NXT 포함` 처럼 서버(계좌 브리핑 저장)와 앱(창·위젯)이 같은 말을 쓰도록 공용 픽스처로 묶습니다. 2차 6 의 가격 줄 `(NXT 포함)`·`(주간거래)`·`(시간외 포함)` 과도 같은 말입니다.
