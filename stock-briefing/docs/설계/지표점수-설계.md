## 2. 비평 (가) — 규정·문구

### 2.1 배경 (법률 자문 아님)

- 자본시장법은 금융투자상품의 **가치나 투자판단에 관해 조언하는 것을 '영업으로'** 하면 투자자문업(등록 대상)으로 봅니다(제6조).
- 불특정 다수에게 간행물·전자 매체 등으로 그런 조언을 하는 것을 영업으로 하면 **유사투자자문업(금융위원회 신고 대상)** 입니다(제101조). 2024년 개정으로 유사투자자문 규제가 더 엄격해졌습니다(양방향 채널 영업 제한, 광고 규제 등).
- 지금 이 앱은 **1인 개인용이고 돈을 받지 않습니다.** '불특정 다수'와 '영업' 요건과 거리가 멉니다. 그래서 지금 가장 큰 위험은 법 위반보다 **사용자 본인의 오해**입니다.
- 그러나 "싼지·재무가 좋은지·추세가 강한지를 한 숫자로" 보여 주는 것은 **내용상 '가치에 관한 조언'과 모양이 같습니다.** 이름과 고지 문구만으로 성격이 바뀌지 않습니다. 나중에 공유·배포·유료화할 계획이 생기면 **공개 전에 전문가 확인**이 필요합니다(질문 7).

| A11 | 고지 누락 | 카드가 여러 곳에 생김 | 카드마다 `참고 정보이며 투자 권유가 아닙니다`, 상세 끝에 전체 고지 + "앞으로의 가격을 알려 주지 않음" 줄 |
| A12 | 원자료 권리 | 네이버 재무는 FnGuide·LSEG 값의 재표시 | 계산 결과 위주로 보이고 원자료 표는 최소. 공개 시 다시 검토 |

### 2.3 이름 고르기

| 후보 | 판정 | 이유 |
|---|---|---|
| 투자 매력도 | 쓰지 않음 | 투자판단을 직접 말함 |
| 가치분석 점수 · 기술분석 점수 | 쓰지 않음 | '분석'이 판단 결과처럼 들리고, 같은 이름의 AI 분석 탭과 헷갈림 |
| **가치 지표 점수 · 추세 지표 점수** | **채택** | '지표' = 숫자 요약. 사용자가 요청한 두 각도(가치·기술)를 알아볼 수 있음 |
| 재무 위치 점수 | 설명 줄에만 | 더 정확하지만 사용자 말('가치')과 멀어짐 |
| **종합 지표 점수** | **채택 (조건부)** | 늘 "(두 점수의 평균)"을 붙이고, 두 점수 없이 혼자 보이지 않음 |

### 2.4 종합 점수를 정직하게 보여 주는 법

1. **평균으로:** 두 점수를 더한 합(0~200)보다 평균(0~100)이 세 줄 모두 같은 눈금이라 읽기 쉽습니다. "두 점수를 더해 2로 나눈 값"이라고 적어 사용자가 말한 '합산'과도 맞춥니다(질문 2).
2. **보이는 숫자로 계산:** 화면에 보이는 두 정수로 계산해, 사용자가 손으로 확인할 수 있게 합니다(57 + 69 → 63).
3. **작게, 아래에:** 두 점수 줄 아래 한 줄. 막대·띠 이름 없음.
4. **차이 안내:** 두 점수 차이가 30 이상이면 "평균만으로는 상태가 잘 드러나지 않습니다" 한 줄(과거 자료에서 4번 중 1번꼴, 3.3).
5. **없으면 없다고:** 둘 중 하나라도 없으면 종합은 `없음`과 이유. 0점·50점으로 채우지 않습니다.
6. **계산 방법에 한계를 적음:** "두 점수는 만드는 방식이 달라 평균의 뜻은 제한적입니다", "지난 11년 자료로 맞춰 보니 점수와 그 뒤 주가의 관계는 우연과 구별하기 어려울 만큼 약했습니다".

### 3.3 두 점수를 하나로 합치는 것이 뜻이 있나 (숫자)

과거 점검 단계의 간이 가치 지표(미국 비금융 117개사, 3묶음·표본 안 백분위)와 추세 점수로 월말 13,739행을 다시 집계했습니다. **실제 가치 점수가 아니라 흉내**라서 모양만 참고합니다.

| 항목 | 값 |
|---|---|
| 가치(간이)·추세 상관 | −0.13 (전체 행) · 달마다 순위상관 평균 −0.16 (점검 문서) |
| 퍼짐(표준편차) | 가치 15.7 · 추세 16.3 · **종합 10.6** |
| 40~60 사이 비율 | 가치 50% · 추세 34% · **종합 58%** |
| 두 점수 차이 ≥ 30 | **25%** (4번 중 1번) |
| 종합 분포 | 5% 34.5 · 중앙 55.2 · 95% 69.9 |
| 종합과 이후 3개월 수익 | 순위상관 −0.001 ~ 0.003 (t 0.1 이하) |

읽는 법
- 싼 종목은 대개 하락 추세라 두 점수가 **서로 반대로** 움직이는 편입니다. 그래서 평균을 내면 가운데(50 근처)로 모이고, "가치 80·추세 20"과 "50·50"이 같은 종합 50이 됩니다.
- 그래서 **두 점수를 늘 따로 보여 주는 것이 본체**이고, 종합은 사용자가 요청한 "한눈 숫자"를 보조로 두는 것입니다.

### 3.4 가중치 제안

| 대상 | 제안 | 이유 |
|---|---|---|
| 가치 5묶음 | 주가 수준 30 · 수익성과 이익의 질 25 · 재무 건전성 20 · 성장 15 · 주주환원 10 (그대로) | 수익률로 고르지 않은 설계값. 바꿀 근거가 없음. 금융사는 35·30·10·15·10 |
| 추세 5묶음 | 추세 35 · 모멘텀 35 · 단기 균형 10 · 가격 안정성 10 · 거래량 뒷받침 10 (그대로) | 5안 비교가 모두 잡음 범위. 설계 원칙(긴 창 중심) 유지 |
| 종합 | **가치 50 : 추세 50** | 어느 쪽에도 더 줄 근거가 없음 → "의견 없음"에 가장 가까운 같은 비중. 손으로 확인 가능 |

버린 안

| 안 | 버린 이유 |
|---|---|
| 가치 60 : 추세 40 (또는 반대) | 근거 없음. 과거 자료로 고르면 과최적화 |
| 표준화(z) 뒤 평균 | 사용자가 손으로 확인할 수 없음 |
| 두 점수 2×2 칸 그림(사분면) | 한 칸이 '좋은 자리'처럼 읽힘 → 추천 모양 |
| 종합을 아예 없앰 | 가장 안전하지만 사용자가 명시적으로 요청함 → 보조로 두고 질문 2에서 확인 |

### 3.5 구현 전에 고칠 것 (체크리스트)

1. `band()` 를 반올림한 정수로 (B10 ①)
2. h 상수를 정확한 식으로 (B10 ②)
3. 네이버 finance `isConsensus=N` 열만, 날짜 키로 정렬, 단위 문자열 확인
4. SEC 개념 별칭 목록 + "겹치는 연도 값이 같을 때만 잇기" 규칙 재사용(기존 `edgar.ts`)
5. 한 종목은 한 일봉 출처로 계산하고 출처 이름을 결과에 저장
6. 레버리지 판별: 토스 `leverageFactor`·`singleStockEtp` → 정적 표 → 이름 규칙 순서
7. 종합은 **두 점수의 가격 기준일이 같을 때만** (다르면 `없음 — 기준일이 달라 합치지 않았습니다`)

## 5. 최종 설계

### 5.1 이름

| 화면 이름 | 뜻 (한 줄) | 서버 키 |
|---|---|---|
| 지표 점수 (카드 제목) | 정해진 계산식으로 숫자의 위치·상태를 요약한 값 | `scores` |
| 가치 지표 점수 (줄 이름 `가치 지표`) | 재무 숫자가 같은 업종·시장 회사들(그리고 이 회사의 지난 5년) 사이 어디쯤인지 | `value` (`value-v1`) |
| 추세 지표 점수 (줄 이름 `추세 지표`) | 최근 1년 가격·거래량 흐름의 방향과 세기 | `trend` (`TREND-1`, `TREND-CAL-1`) |
| 종합 지표 점수 (줄 이름 `종합 지표`) | 두 점수의 평균 | `composite` |

### 5.2 계산 요약

**가치 지표 점수 V** (가치 지표 방법 설계서(value-v1) 그대로, 바뀐 점은 7장)
- 지표 약 20개 → 5묶음: 주가 수준(이익·영업이익/기업가치·순자산·매출·잉여현금흐름 대비 주가), 수익성과 이익의 질(ROE·ROIC·매출총이익/자산·영업이익률·이익 안정성·이익의 현금 뒷받침), 재무 건전성(부채비율·순차입금/영업이익·이자보상·유동성), 성장(3년 매출·주당이익 증가폭·이익률 변화), 주주환원(배당수익률·주식 수 변화).
- 지표마다 백분위 `p = 100 × (#{작음} + 0.5 × #{같음}) / N`, 비교 섞기(주가 수준: 업종 50·시장 20·자기 5년 30 등, 없는 비교는 비례 배분).
- `V = round( Σ 묶음 비중 × 묶음 점수 / Σ 유효 묶음 비중 )`
- 적자 → 이익 기준 지표 0점, 자본 ≤ 0 → 해당 지표 계산 안 함(표시), 무배당 = 0%(유효 값).
- 한국: DART 키 전까지 **간이 등급**(네이버 요약 재무 3년), 미국: **전체 등급**(SEC).
- 띠: 0~33 `낮은 편` · 34~66 `가운데쯤` · 67~100 `높은 편` (보이는 정수로 정함, 여유 없음).

**추세 지표 점수 T** (`추세지표-계산.md` 그대로)
- 끝난 일봉 최근 300개 + 비교 지수. 16항목 → 5묶음: 추세(200·50일선 거리·기울기), 모멘텀(12·6·3개월, 최근 1개월 제외, 지수 대비), 단기 균형(RSI·볼린저·50일선 거리, 과열·과매도에서 멀수록 높음), 가격 안정성(변동성·52주 고점 대비·1년 최대 낙폭), 거래량 뒷받침.
- 원값을 랜덤워크 척도로 z 로 바꾼 뒤 고정 로지스틱 `S(x; c) = 100 / (1 + e^(−x/c))` → 50 = "뚜렷한 추세 없음".
- `그날 점수 = Σ W·F / Σ W(유효)`, **화면 점수 = 최근 5거래일 그날 점수의 평균**, 띠는 반올림한 정수로.
- 띠: 70~100 `강함` · 55~69 `다소 강함` · 45~54 `중립` · 30~44 `다소 약함` · 0~29 `약함`.
- 레버리지(정방향): 기초자산 봉으로 계산하되 **화면에서는 참고 줄**(5.7-C). 인버스·채권형: 대상 아님.

**종합 지표 점수 C**
```
C = floor( (V + T) / 2 + 0.5 )      # V, T 는 화면에 보이는 정수
조건: V 상태 ∈ {ok, partial, lite} 이고 T 상태 = ok(본인 봉) 이고 두 가격 기준일이 같음
그 밖: C = 없음 (이유 코드: valueMissing | trendMissing | bothMissing | dateMismatch | etf | leveraged)
차이 안내: |V − T| ≥ 30 이면 gapNote = true
```

### 5.4 자료 부족·대상 아님 규칙

**한 점수의 상태 → 화면 말**

| 서버 상태 | 언제 | 화면 (요약 카드 줄) |
|---|---|---|
| `ok` | 모두 계산 | 숫자 + 띠 |
| `partial` (가치) | 유효 묶음 비중 70~99 | 숫자 + 띠 + 배지 `일부 지표 없이 계산` |
| `lite` (가치 등급) | 한국, DART 키 없음 | 숫자 + 띠 + 배지 `간이 계산` |
| `excluded` | ETF·ETN·스팩·우선주·리츠(가치), 인버스·채권형(추세) | `대상 아님` + 이유 한 줄 |
| `insufficient`·`unavailable` | 기록·재무 모자람, 받기 실패 | `점수 없음` + 이유 한 줄 |
| `hold` (추세) | 분할·병합 의심 | `잠시 보류` + 이유 |
| `pending` | 재무를 받는 중·첫 비교 기준을 만드는 중(서버가 실제로 받는·만드는 중일 때만 — 2단계 3차), 가치 부분을 끈 서버 | `계산 준비 중` + 이유 (끈 서버는 `지금 계산하지 않음`) |
| 받기 실패 (지난 값 있음) | 7일 안 | 지난 숫자 + 배지 `지난 값 9/24` |

**두 점수 조합 → 종합**

| 가치 | 추세 | 종합 |
|---|---|---|
| ok · partial · lite | ok | 평균 |
| excluded (일반 ETF, 예: QQQ) | ok (본인) | `없음 · 가치 지표 점수가 없어 합치지 않습니다` |
| excluded (레버리지 ETF) | 기초자산 참고만 | `없음 · 가치 지표 점수가 없어 합치지 않습니다` |
| excluded (인버스) | excluded | `없음 · 두 점수가 모두 없습니다` |
| insufficient | ok | `없음 · 가치 지표 점수가 없어 합치지 않습니다` |
| ok | unavailable · hold | `없음 · 추세 지표 점수가 없어 합치지 않습니다` |
| 가격 기준일 다름 | | `없음 · 두 점수의 기준일이 달라 합치지 않았습니다` |

규칙: 없는 점수를 0점이나 50점으로 채우지 않습니다. 없는 이유는 사람이 읽는 말로 남깁니다(받기 실패 / 원래 없음 / 계산 불가를 구분 — 저장소 BH-43 원칙).
