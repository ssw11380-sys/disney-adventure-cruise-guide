## 3. 재무 만들기 (`secFacts.ts`)

### 3.1 공시일 기준 (미래 자료를 섞지 않음)
- 기준일(asOf)까지 **제출된(filed ≤ asOf)** 줄만 쓴다. 같은 기간 값이 여럿이면 그날까지 가장 늦게 낸 값(정정·재작성 반영).
- 정기 보고서(10-K · 10-Q · 정정 · 10-KT)만. 8-K 등은 버린다.

### 3.2 최근 4분기 (TTM)
- **E** = 기준일까지 제출된 가장 최근 보고서의 기간 끝(순이익·매출 기간 값 기준).
- E 에 끝나는 **회계연도 값**(1년 길이이고 **10-K 에 나온** 기간)이 있으면 그 값 — 예: MSFT 2026-06-30(10-K 2026-07-29 제출).
- 아니면 `직전 회계연도 + 올해 누적(E 까지) − 작년 같은 기간 누적`. 10-Q 현금흐름은 연초부터의 누적값만 있어서 이렇게 뺀다 — 예: NVDA = FY2026(2025-01-27~2026-01-25) + 6개월(2026-01-26~07-26) − 6개월(2025-01-27~07-27), AAPL 은 9개월.
- 1년 길이라도 10-Q 에만 나온 '최근 12개월' 줄(AMZN 이 보고)은 회계연도가 아니다 — 누적값 빼기로 계산하고 연간 이력에도 넣지 않는다.
- 52/53주 회계연도: 기간 길이 ±12일, 직전 회계연도 끝은 올해 시작 하루 전 ±7일로 찾는다.

### 3.3 태그 별칭 (`valueConcepts.ts`, 대상 종목과 비교 회사 공통)
| 항목 | 태그 (앞쪽 우선) | 예 |
|---|---|---|
| 매출 | Revenues · RevenuesNetOfInterestExpense · RevenueFromContractWithCustomerExcluding/IncludingAssessedTax · SalesRevenueNet (없으면 은행: InterestIncomeExpenseNet + NoninterestIncome) | JPM 순영업수익 |
| 영업이익 · 순이익 | OperatingIncomeLoss · NetIncomeLoss(없으면 ProfitLoss) | AVGO 2025~ ProfitLoss |
| 설비투자 | PaymentsToAcquirePropertyPlantAndEquipment · PaymentsToAcquireProductiveAssets | NVDA 2024~ 뒤 태그 |
| 이자비용 | InterestExpense · InterestExpenseNonoperating · InterestExpenseDebt | NVDA·MSFT 2025~ Nonoperating, META Debt |
| 배당 지급 | PaymentsOfDividendsCommonStock · PaymentsOfDividends · PaymentsOfOrdinaryDividends · DividendsCommonStockCash · DividendsCommonStock (없으면 주당 배당 × 주식 수) | BAC·JNJ 뒤쪽 태그 |
| 단기금융상품 | MarketableSecuritiesCurrent · ShortTermInvestments · DebtSecuritiesCurrent · AvailableForSale…Current | NVDA 2026~ DebtSecuritiesCurrent |
| 장기차입금 | LongTermDebt(유동 포함) → LongTermDebtNoncurrent·LongTermDebtAndCapitalLeaseObligations + LongTermDebtCurrent·…ObligationsCurrent → DebtCurrent | KO·PEP·T·HD 리스 합친 태그 |
- 한 회사에서는 **가장 최근 기간 값이 있는 태그를 먼저** 쓰고, 그 태그에 없는 기간만 다른 태그로 채운다. **겹치는 기간 값이 다른 태그는 쓰지 않는다**(이름만 바꾼 태그는 겹침이 없거나 값이 같다).
- 빈 칸 채우기(`normalizeInputs`, 두 쪽 공통): 지배주주 자본이 없으면 자본총계 − 비지배지분(AVGO), 부채총계가 없으면 자산 − 자본총계.
- 총차입금 = 장기차입금(유동 포함) + 단기차입금·기업어음(DebtCurrent 로 채웠으면 더하지 않음) + 리스부채(운용·금융). **차입 태그가 하나도 없는데 이자비용이 있으면 빚을 '모름'**으로 둔다 — 0 으로 보면 '순현금'으로 맨 위에 오르므로(KO 가 그랬음). 그때 EV·ROIC·순차입금 부담은 계산하지 않는다.
- 현금 = 현금및현금성자산 + 단기금융상품.

## 4. 지표 (`valueMetrics.ts`)

순위용 값 x 는 클수록 점수가 높다. 규칙: `0점`(x = −∞, 위치와 상관없이 0), `맨 위`(x = +∞, 같은 규칙 회사끼리 같은 순위), `계산 안 함`(x 없음).

| 묶음 | 지표 | 식 | 규칙 | 화면 값 |
|---|---|---|---|---|
| 주가 수준 | A1 PER | 순이익 ÷ 시가총액 (경기 민감이면 ½ 최근 4분기 + ½ 5년 평균 순이익) | ≤ 0 → 0점 | 배 |
| | A2 기업가치 ÷ 영업이익 | 영업이익 ÷ (시가총액 + 총차입금 + 비지배지분 − 현금) | 영업이익 ≤ 0 → 0점, EV ≤ 0 → 맨 위 | 배 |
| | A3 PBR | 자본 ÷ 시가총액 | 자본 ≤ 0 → 계산 안 함 | 배 |

## 6. 점수 (`valueScore.ts`)

```
지표 위치 p_k = 100 × (#{작음} + 0.5 × #{같음}) / N      (k = 업종 자리 · 시장 · 자기 지난 5년, 대상 종목 자신은 모집단에서 뺌)
지표 점수 S = Σ w_k p_k / Σ w_k                         (없는 비교는 남은 비교에 비례 배분. 0점 규칙이면 S = 0)
묶음 점수 F = 값이 있는 지표의 화면 정수 round(S) 의 평균   (핵심 지표가 있고, 정의된(채택된) 지표의 절반 이상일 때만 유효)
V = round( Σ W_f round(F_f) / Σ W_f )                   (f = 유효한 묶음, round 는 0.5 올림 — 화면 정수로 한 단계씩)
```
- 예: 애플 묶음 정수 34·85·29·49·80 → (30·34 + 25·85 + 20·29 + 15·49 + 10·80) / 100 = 52.60 → **53**. 1차 코드는 소수 묶음 점수로 계산해 손계산과 1점 어긋날 수 있었다(검토 지적 — 묶음 0·46·81·24·32 가 34.5 인데 34).
- 업종 자리: 같은 경로(일반·금융) 안에서 그 지표 값이 **15곳 이상**인 첫 층 — Nasdaq 업종 → 부문 → 시장. 비교 기준의 층 표(5장 6)에 이번 주 층이 있으면 그 층(두 주 연속 조건이 바뀌어야 바뀜, 그 층 값이 10곳보다 적으면 그 자리에서 다시 정함). 업종 대신 부문·시장이면 '같은 업종 회사가 적어 … 전체와 비교했습니다' 표시.
- 같은 값이 많은 지표: 업종 자리 비교 회사의 절반 이상이 한 값(무배당 0% 등, 규칙 값 ±∞ 는 뺌)이고 이 회사 값은 그 값과 다르면, 지표 줄에 '비교한 회사의 77%가 같은 값(0.0%)이라, 그 값과 조금만 달라도 위치 점수가 크게 달라집니다.'를 붙이고 그 지표는 묶음 머리 문장으로 고르지 않는다(예: 엔비디아 배당수익률 0.1% 가 반도체 회사 대부분의 0% 위라 위치 74 — 머리 문장이 '배당이 많은 편'으로 읽히던 것).
- 비교 섞는 비율: 주가 수준 업종 50 · 시장 20 · 자기 30 / 수익성 70·30 / 건전성 50·50 / 성장 60·40 / 주주환원 50·50. 실제로 쓴 비율을 지표 줄에 적는다('업종 71 · 시장 29').
- 상태: 주가 수준 묶음이 없으면 점수 없음 '주가 수준을 계산할 재무 숫자가 없습니다' · 유효 비중 < 70 '쓸 수 있는 지표가 모자랍니다 (필요한 비중 70, 지금 n)' · 유효 묶음 < 3 · 비중 100 → ok, 70~99 → partial.

## 10. 지난주 대비 바뀐 이유 (상세 카드만)
- 5거래일 전 봉까지 · 그날까지 제출된 재무 · 그날 쓰던 비교 기준으로 같은 식을 다시 계산(저장한 기록이 없어도 같은 값). 화면 정수 차이가 **5점 넘을 때만**.
- 묶음: 점수와 같은 쪽으로 움직인 묶음 가운데 비중 × 변화가 가장 큰 것. 까닭: 새 보고서(제출일이 다름) → 주가(주가 수준 묶음이고 20일 평균이 3% 넘게 움직임) → 비교 기준(기준일이 다름) → 주가.
- 예: '지난주 9월 18일(금)보다 점수가 8점 낮아졌습니다. 가장 크게 바뀐 묶음은 주가 수준(−25점)이고, 최근 20거래일 평균 주가가 10.0% 올랐습니다.'

## 11. 종합 지표 (설계 5.2·5.4)
- `C = floor((V + T) / 2 + 0.5)` — **화면에 보이는 두 정수**로(손으로 확인 가능). 가치가 ok·partial, 추세가 본인 봉으로 ok, 두 가격 기준일이 같을 때만.
- `|V − T| ≥ 30` 이면 '두 점수의 차이가 d점이라 평균만으로는 상태가 잘 드러나지 않습니다. 두 점수를 함께 보세요.'
- 없으면 '없음 · 가치 지표 점수가 없어 합치지 않습니다' / '… 추세 지표 점수가 없어 …' / '두 점수가 모두 없습니다' / '두 점수의 기준일이 달라 합치지 않았습니다'. 0점·50점으로 채우지 않는다.

## 12. 문구
- 모든 문장은 서버 틀(`valueScoreText.ts`)에 숫자를 채운다. 앱에 고정된 글은 줄 이름·버튼뿐.
- 계산 방식·출처 줄('계산 방식 VALUE-1 · 재무 SEC … · 업종 분류 Nasdaq · 비교 기준 M월 D일')은 **점수를 계산했을 때만** 둔다 — 한국·ETF·점수 없음 카드가 SEC 자료로 계산한 것처럼 읽히지 않게.
- 요약 줄 글(`label`)은 점수가 있으면 '67점 · 높은 편' — 예전 앱(1단계 OTA)은 이 글만 굵게 보이므로 숫자까지 넣는다(새 앱은 score·band 를 쓴다).
- 화면 읽기: 지표 줄은 한 덩어리로 읽히므로 보이는 글(값·가운데값·위치 점수·비교별 위치('100 중 72')·비중·문장·안내·뜻)을 모두 담는다.
- 지표 문장은 위치 67 이상 '높을 때' · 33 이하 '낮을 때' · 그 사이 '비교한 회사들 가운데쯤입니다.' — 현재·과거의 위치만 말한다('이익에 비해 주가 수준이 높은 편입니다').
- 금지어·미래형 검사(`analysis/scoreWording.ts`)를 모든 틀 조합과 응답 전체에 테스트로 적용. 허용한 미래형은 계산 방식 설명뿐('조금 다를 수 있습니다', '좋아 보일 수 있습니다' 등).
- 가운데값이 100배를 넘는 배수(적자 회사가 많은 업종의 PER 가운데값 등)는 '100배 넘음', 가운데값이 적자면 '적자'.

## 14. 한계 (솔직하게)
1. **비교 시점이 다르다 (한쪽으로 치우침)**: 비교 회사의 흐름 값은 frames 의 '가장 최근 회계연도'(최대 약 1년 앞, 1~3월에는 더 앞)이고 시가총액은 스크리너의 그날 값, 대상 종목은 최근 4분기와 20거래일 평균. frames 는 6·9개월 누적 현금흐름을 주지 않아 비교 회사의 최근 4분기를 만들 수 없다. **이익이 빠르게 늘고 있는 회사는 주가 수준 점수가 높은 쪽으로 치우친다** — 예: 엔비디아 최근 4분기 순이익(1,928억 달러)은 직전 회계연도(1,201억 달러)보다 61% 많은데, 비교 회사는 더 앞선 연간 값이다. 상세 카드에 '… 이익이 빠르게 늘고 있는 회사는 이 차이로 주가 수준 점수가 조금 높게 계산되는 편입니다' 한 줄.
2. 비교 회사의 연간 자산·자본은 12월 말 잔액으로 근사(6월 결산 회사는 반년 차이) — 주당이익 증가폭 분모·ROE 안정성에만 쓰인다.
3. 이자보상배율·매출총이익 ÷ 자산은 지금 채택 비율이 70% 에 못 미쳐 쓰지 않는다(태그가 흩어져 있음).
4. 분할 직후 다음 보고서 전까지는 SEC 주식 수가 분할 전이라 시가총액이 틀릴 수 있다 — 추세 쪽이 분할을 의심하면 '잠시 보류'로 함께 멈추고, 봉이 이미 보정된 출처여도 **주식 수 확인**(2장 10b)이 비교 기준의 Nasdaq 주식 수·시가총액과 견주어 '잠시 보류'로 멈춘다. 다만 비교 기준을 만든 뒤(최대 1주) 생긴 3:1 보다 작은 분할(2:1 등)은 다음 주 기준까지 잡지 못할 수 있다. 여러 종류 주식 회사(상장 종류만 Nasdaq 시가총액)는 SEC 주식 수가 커 보여도 멈추지 않게 '크다' 쪽 기준을 8배로 넉넉히 두었다.
5. IFRS·외국 통화로 보고하는 회사(20-F)는 계산하지 않는다. Nasdaq 업종 분류는 거칠다(SPGI·MCO 가 '금융 서비스').
6. Nasdaq 스크리너는 비공식 공개 JSON — 모양이 바뀌면 비교 기준을 만들지 못하고 14일 뒤 '점수 없음'.
7. 설계 단계 과거 점검에서 가치 쪽 간이 지표는 앞날 수익과 오히려 반대 방향이었다 — 점수는 '지금 숫자 상태 요약'일 뿐이다.
8. 회계연도 끝을 바꾼 회사는 바꾼 해에 비교 회사의 가장 최근 회계연도가 한 해 앞 값이 되거나(앞 값이 18개월 안일 때) 빠질 수 있다(5장 2).
9. ROIC 투하자본은 평균이 아니라 최근 분기말 값이다(17장 11번) — 한 해 사이 자본·빚이 크게 바뀐 회사는 설계 값과 다를 수 있다.
