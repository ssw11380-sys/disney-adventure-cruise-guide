## 0. 쉬운 요약

1. 아이디로 로그인한다. 지금까지의 데이터는 모두 아이디 **'서성원'** 것이다. 처음 비밀번호는 **1111** 이고 설정에서 바꾼다(강제하지 않음 — 로그인 직후 한 번 권유, 설정 맨 위 띠).
2. 회원가입은 네 칸: 아이디, 비밀번호, 비밀번호 확인, 이메일. 가입하면 바로 로그인.
3. 한 번 로그인하면 거의 풀리지 않는다. '자동 로그인'(기본 켬)이면 1년, 쓰는 날마다 1년이 다시 늘어난다. 인터넷이 끊기거나, 서버가 잠깐 멈추거나, 앱이 업데이트돼도 로그아웃되지 않는다. 로그아웃은 ① 직접 ② 다른 기기에서 '모든 기기에서 로그아웃'·비밀번호 변경 ③ 1년 넘게 안 씀 뿐.
4. 새로 가입한 사람은 서성원님 데이터를 볼 수 없다 — **서버가 막는다**. A단계에서 새 계정은 시장·종목 정보만 본다.
5. 새 계정도 자기 종목을 쓰게 하는 것은 B단계(표마다 '누구 것인지' 칸, 토스 키 사람마다 암호화).
6. 문제가 생기면 끌 수 있다: 플래그를 끄면 지금과 똑같다. 로그인이 안 돼 관리 API 를 못 쓰면 Railway 변수 `ACCOUNTS_DISABLED=1`.

## 2. 표 (마이그레이션 11 — 새 표만, 백업 포함 `users` → `sessions` · 마이그레이션 12 — `devices.session_id` 한 칸)

- `users(id, login_id, login_id_key UNIQUE, email UNIQUE(NULL 여러 개 허용), password_hash, is_owner, initial_password, created_at, updated_at)` + 주인 한 명 부분 유일 색인 `where is_owner = 1`
- `sessions(id, user_id → users ON DELETE CASCADE, token_hash UNIQUE, remember, device_label, created_at, last_seen_at, expires_at, revoked_at)`
- 시각은 `seoulIso()` 글자. 끝난 세션(기한 지남·끊긴 지 30일)은 켠 뒤 1분·하루 한 번 지운다(그 세션으로 등록한 기기 행도).
- 마이그레이션 12(보강): `devices` 에 비어 있을 수 있는 `session_id`(FK 없음) + 색인. 예전 행은 NULL = 계정 전 등록(주인 기기, 예전처럼 보냄). 예전 서버로 되돌려도 이 칸을 모르고 지나갈 뿐.
- 백업을 되살리면 바꾼 비밀번호·로그인이 그대로(테스트). 주인이 없는 옛 백업이면 켤 때 1111 로 만든다.

## 4. 앱

- `lib/session.ts`(React 없는 모듈 — 앱·위젯·백그라운드 공용, 저장소는 `lib/sessionStorage.ts` 가 AsyncStorage 를 끼움): 저장·서버 주소 짝(그 서버에만 보냄)·`handleSessionInvalid(보낸 토큰)`(지금 토큰일 때만 지움)·계정 모드 기억(`auth.device.v1`, 토큰 없음)·자동 로그인 선택(`auth.rememberPref.v1`)·fail-open·권유 시트 한 번.
- 머리글: `api/client.ts` 의 요청 전부(로그인·가입 빼고), 위젯·백그라운드(`widgets/data.ts`·`lib/marketSummaryLoad.ts` — 기기 저장 세션), 실시간 스트림(주인 아닌 계정·로그인 전에는 열지 않음).
- 연결 오류 판정(`lib/connectionError.ts`)에서 `SESSION_INVALID`·`SESSION_REQUIRED`·`PERSONAL_DATA_NOT_READY` 는 연결 오류가 아님.
- 관문(`lib/authGate.ts` + `_layout` 의 `Stack.Protected`): 이 서버의 세션이 있으면 바로 앱(인터넷이 없어도), 없고 계정 모드(받은 플래그, 모르면 이 기기가 본 적 있는지)면 로그인·회원가입만. '서버 설정'(`/server`)은 늘 열림. 설정·세션을 읽기 전에는 바꾸지 않음(스플래시가 가림).
- 계정이 바뀌면(다른 사람으로 로그인·로그아웃·세션 끊김) **세션을 바꾸는 그 자리에서, 화면을 다시 그리기 전에** react-query 캐시·기기 저장 캐시·조건부 요청 기억을 비움(`lib/session` `onAccountChange` → `components/AuthBridge.tsx`, 보강 — 예전에는 탭을 그린 뒤 비워 앞 사람 잔고가 한 번 보일 수 있었다). 위젯이 적어 둔 개인 데이터(마지막 잔고·마지막 `/api/widget` 응답·그린 데이터)도 지우고 위젯을 '로그인 필요'로 다시 그림(`_layout`). 위젯 스스로도 401 `session_invalid`·403 `session_required`·403 `personal_data_not_ready` 를 받으면 마지막 잔고로 그리지 않고 지움. `/api/auth/me` 는 켤 때 한 번 + 앞으로 돌아왔을 때 6시간 넘었으면. 받은 플래그를 기기에 적는 것은 설정(서버 주소)을 다 읽은 뒤에만.
- 알림(보강): 로그아웃은 서버 등록만 빼고 기기 토큰(알림을 켜 둔 기록)은 남김 → 주인으로 다시 로그인하면(또는 비밀번호를 바꾸면) 새 세션으로 다시 등록(`rebindPush`). 인터넷이 끊긴 채 로그아웃해 서버에 알리지 못한 세션은 기기에 적어 두고(`auth.pendingLogout.v1`) 켤 때·돌아올 때 그 토큰으로 다시 알림.
- 주인 아닌 계정 화면(보강): 브리핑 탭 빈 칸은 '종목 브리핑은 준비 중이에요'(종목 추가 말·버튼 없음), 종목 상세의 [관심 추가]·아래 막대 별 버튼 없음, 종목 검색의 '등록' 칸 없음(누르면 상세).

## 5. 배포 순서·되돌리기

0. **병합 준비**: 이 브랜치는 b081800(3-39) 위에 있다. 지금 main(9206f1e — 3-46 차트 최고·최저가, 앱 이름·아이콘·APK 1.5.0)과 `settings.tsx`·`featureService.ts`·`features.test.ts`·`기능-플래그.md`·`로드맵.md`·`진행상황.md` 가 겹치므로 병합할 때 양쪽을 합친다(플래그 목록은 둘 다 남김). 마이그레이션 번호 11·12 는 main 에 없다(main 은 10 까지).
1. 병합. 병합 뒤 앱 버전은 1.5.0 → OTA 는 **APK 1.5.0 이 깔린 폰에만** 간다. 폰의 설정 > 앱 업데이트 '현재 버전'이 1.5.0 인지 먼저 본다(아니면 1.5.0 APK 설치가 먼저 — 사용자에게 알림).
2. **앱 OTA 먼저** — 서버가 아직 플래그를 안 주므로 변화 없음. 폰에서 앱을 껐다 켜 새 묶음을 받고, 설정 > 앱 업데이트에서 새 묶음으로 도는지 확인한다. **서버의 `accounts` 는 기본 켜짐이라, 새 묶음이 없는 앱은 서버 배포 뒤 모든 개인 경로가 403 `session_required` 이고 OTA 로도 고칠 수 없다** → 확인 전에는 3 으로 가지 않는다(서두르면 Railway 변수 `ACCOUNTS_DISABLED=1` 로 먼저 배포하고, 확인 뒤 변수를 지운다).
3. 서버 배포 — 마이그레이션 11·12, 주인 시드, 플래그 켜짐 → 앱이 1분 안에 로그인 화면 → '서성원'/처음 비밀번호 → 비밀번호 변경. **가능하면 첫 배포 전에 Railway 변수 `OWNER_INITIAL_PASSWORD` 를 넣어 둔다**(공개 저장소의 1111 이 처음부터 통하지 않게 — 넣었으면 그 값으로 로그인).
4. 확인: 위젯·백그라운드 알림이 계속 오는지(자동 로그인 켬 — 로그인 뒤 알림 등록이 새 세션에 다시 묶인다), 설정 맨 위 '처음 비밀번호를 쓰고 있어요' 띠가 사라졌는지(`/health` 는 이제 이 값을 내보내지 않는다).
5. 문제 시: 주인 세션으로 `PUT /api/admin/features {"accounts": false}`, 로그인이 안 되면 Railway 변수 `ACCOUNTS_DISABLED=1`(앱에도 플래그를 꺼짐으로 줌). 앱은 OTA 되돌리기(`docs/OTA-되돌리기.md`). **알아 둘 것**: 끄면 세션 없이 API 토큰만 가진 요청은 다시 주인으로 본다(지금까지와 같음). 주인 아닌 계정의 앱은 세션을 계속 보내므로 서버가 그 계정으로 막아 주인 데이터가 보이지 않지만, API 토큰을 가진 사람이 세션 없이 부르면 막지 못한다 — 끈 채로 오래 두지 않는다.
6. 누가 먼저 1111 로 들어와 비밀번호를 바꿨다면: Railway 변수 `OWNER_RESET_PASSWORD=<새 비밀번호>` 로 다시 배포 → 주인 비밀번호가 그 값으로 바뀌고 주인 세션·알림 기기가 모두 끊긴다 → 로그인 뒤 **변수를 지우고** 다시 배포.

## 6. 알아 둘 한계 (A단계)

- API 토큰은 앱 묶음(`EXPO_PUBLIC_API_TOKEN`) 안에 있어 마음먹은 사람은 꺼낼 수 있다 → 1111 은 알려진 비밀번호이므로 빨리 바꾼다. B단계 전에는 다른 사람에게 토큰을 주지 않는 것을 권한다.
- 자동 로그인을 끄면 앱을 닫은 뒤 위젯·백그라운드 알림이 개인 데이터를 받지 못한다(세션이 메모리에만 있음).
- 잠금·속도 제한은 서버 메모리라 재배포하면 초기화된다(지금 Railway 1대).
- Android 자동 백업에 AsyncStorage(세션 토큰 포함)가 들어갈 수 있다 → 다음 APK 때 `android.allowBackup: false` 검토.
- 비밀번호 찾기(메일 서비스)·회원 탈퇴·로그인 기기 목록은 아직 없다. 주인만 비상 되돌리기(`OWNER_RESET_PASSWORD`)가 있다.
- 같은 아이디 5번 틀림 잠금(10분)은 남이 일부러 주인을 10분 동안 새 로그인·비밀번호 변경에서 막는 데 쓰일 수 있다(이미 로그인한 기기는 그대로). B단계에서 IP·기기 기준으로 나누기를 검토.
- 폰에서 아직 못 본 것(웹 캡처·테스트만): 키보드가 뜰 때의 부드러운 스크롤, react-native-svg 안드로이드의 가로·세로가 다른 타원 불꽃 그러데이션, 삼성 글꼴의 금색 그러데이션 글자, 933×704 빛 층 하드웨어 텍스처 60fps(개발자 옵션 GPU 막대). 이상하면 `WORDMARK_GRADIENT` 로 단색 로고.
- 로고는 명세대로 3.7초에 나온다 → 첫 3.7초는 브랜드 없이 봉만 보인다. 로고를 처음부터 옅게 보여 주는 것은 명세를 바꾸는 일이라 사용자 확인 뒤에.

## 7. B단계 계획 (요약)

1. 표마다 `user_id`(`registered_stocks` 는 PK `(user_id, code)`, 기존 행은 주인), 개인 `meta` 키는 `user_meta`로. 서비스 메서드에 `userId`.
2. 사람마다 토스 키 — AES-256-GCM(`CREDENTIALS_KEY`), 복호화는 쓸 때만. 토스 Open API 약관(다른 사람 키를 서비스가 대신 쓰는 것) 확인이 먼저.
3. 푸시 기기·위젯·스트림을 사람별로, 그 뒤 세션 없는 요청(API 토큰만)의 개인 데이터 0.
4. 종목 브리핑 = 공유 본문(보유 정보 없음) + 사람별 보유 덧붙임(코드 계산) → 모델 호출 수가 사람 수에 비례하지 않게. 사람별·전체 AI 비용 상한.
