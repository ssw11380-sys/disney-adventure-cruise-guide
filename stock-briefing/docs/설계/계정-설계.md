## 0. 쉬운 요약

1. 아이디로 로그인한다. 지금까지의 데이터는 모두 아이디 **'서성원'** 것이다. 처음 비밀번호는 **1111** 이고 설정에서 바꾼다(강제하지 않음 — 로그인 직후 한 번 권유, 설정 맨 위 띠).
2. 회원가입은 네 칸: 아이디, 비밀번호, 비밀번호 확인, 이메일. 가입하면 바로 로그인.
3. 한 번 로그인하면 거의 풀리지 않는다. '자동 로그인'(기본 켬)이면 1년, 쓰는 날마다 1년이 다시 늘어난다. 인터넷이 끊기거나, 서버가 잠깐 멈추거나, 앱이 업데이트돼도 로그아웃되지 않는다. 로그아웃은 ① 직접 ② 다른 기기에서 '모든 기기에서 로그아웃'·비밀번호 변경 ③ 1년 넘게 안 씀 뿐.
4. 새로 가입한 사람은 서성원님 데이터를 볼 수 없다 — **서버가 막는다**. A단계에서 새 계정은 시장·종목 정보만 본다.
5. 새 계정도 자기 종목을 쓰게 하는 것은 B단계(표마다 '누구 것인지' 칸, 토스 키 사람마다 암호화).
6. 문제가 생기면 끌 수 있다(비상 모드): 플래그를 끄거나, 로그인이 안 돼 관리 API 를 못 쓰면 Railway 변수 `ACCOUNTS_DISABLED=1`. **비상 모드에서는 계정 전처럼 API 토큰만 있으면 주인으로 본다.** 막는 것은 '주인 아닌 계정의 세션을 보낸 요청'뿐이고, 로그아웃했거나 앱을 다시 깐 가입자 폰·API 토큰을 꺼낸 사람은 막지 못한다 → **가입자가 한 명이라도 있으면, 비상 모드를 켜기 전에 API 토큰(Railway `API_TOKEN`)을 새 값으로 바꾸고 새 값은 주인 폰에만 넣는다**(설정 → 서버 연결 → API 토큰). 자세히는 5장.
7. 비상 모드가 아닐 때는 **API 토큰만으로는 주인 데이터가 하나도 나가지 않는다**(로그아웃·세션 끝·다시 설치한 폰, 위젯·백그라운드 알림·푸시 모두) — 주인 세션이 있어야 한다.
8. 새 계정은 주인의 수량·평단·손익·브리핑을 볼 수 없지만, **응답 속도로 주인이 어떤 종목을 등록했는지는 짐작할 수 있다**(서버가 주인 등록 종목의 시세·차트·점수를 미리 받아 두어 빠름 — 3장 '남는 것'). B단계에서 없앨 때까지 가입은 아는 사람에게만 알린다.

| 푸시 기기 (보강) | 등록(`POST /api/devices`)에 로그인 세션을 적는다(`devices.session_id`, 마이그레이션 12). 로그아웃은 그 세션의 기기, 모든 기기에서 로그아웃은 그 사람의 모든 세션 기기(주인은 계정 전 — 세션 없이 — 등록한 기기도), 비밀번호 변경은 다른 세션 기기(주인은 계정 전 등록도)를 지운다. 끊긴·기한 지난·지운 세션의 기기에는 보내지 않는다(`enabledTokens`). 앱은 주인으로 로그인·비밀번호 변경 뒤 알림을 켜 둔 기기면 새 세션으로 다시 등록 |

| 비상 모드 (플래그 끔 · `ACCOUNTS_DISABLED=1`) — 무엇을 막고 무엇을 못 막나 (4차에서 정확히) | 비상 모드 = 계정 전과 같다: **세션 머리글이 없는 요청은 API 토큰만 맞으면 주인**(세션을 쓸 수 없을 때 주인이 앱을 쓰게). **막는 것**: 주인 아닌 계정의 세션 토큰을 보낸 요청 — 살아 있는 세션뿐 아니라 기한이 지났거나 끊긴 세션도(4차) — 은 그 계정으로 경로 정책을 적용(개인 읽기 빈 값·쓰기 403·알림 기기 등록 403, `/health` 공유 모습). **못 막는 것**: 로그아웃한·앱을 다시 깐 가입자 폰(세션 머리글이 없음), API 토큰을 꺼낸 사람, 세션 확인이 DB 오류일 때(그때는 주인으로 — 비상 모드가 DB 오류로 막히지 않게), 그 세션 행을 지운 뒤(청소 30일). 그래서 **운영 규칙: 가입자가 있으면 비상 모드를 켜기 전에 Railway `API_TOKEN` 을 새 값으로 바꾸고, 새 값은 주인 폰에만 넣는다(설정 → 서버 연결 → API 토큰)** — 옛 토큰을 가진 폰은 401 이라 아무것도 못 본다. 앱은 플래그가 꺼져 있을 때 지금 서버에 주인 아닌 계정 세션이 있으면 안내 띠와 설정 '계정' 칸(아이디 + '로그인 기능이 잠시 꺼져 있어요. 다시 켜지면 여기에서 로그아웃할 수 있어요.')을 보이고, **세션을 계속 보낸다 — [로그아웃] 없음**(5차: 4차에 넣은 [로그아웃]은 서버가 404 라 세션만 잊게 했고, 그 뒤 요청은 API 토큰만 = 주인이라 그 폰에 주인 잔고·브리핑이 보였다. 로그아웃이 404 면 주인 아닌 계정의 세션은 지우지 않는다 — `lib/logout`) |
| 세션 캐시 (보강) | 30초 캐시. 끊을 때마다 세대 번호를 올려, 끊기 전에 DB 를 읽기 시작한 요청이 끊긴 세션을 다시 캐시에 넣지 않게 |
| 비상 주인 비밀번호 되돌리기 (보강·3차) | Railway 변수 `OWNER_RESET_PASSWORD`: 켤 때 지금 비밀번호와 다르면 그 값으로 바꾸고(처음 비밀번호 표시 끔) 주인 세션·기기 등록을 모두 끊고 잠금을 푼다. **같은 값은 한 번만** 적용(적용한 값의 scrypt 해시를 meta `accounts.ownerResetApplied` 에) — 변수를 지우는 것을 잊고 앱에서 비밀번호를 바꾼 뒤 다시 배포해도 되돌리거나 로그아웃시키지 않는다. 다른 값을 넣으면 다시 적용. 쓴 뒤 지우는 것을 권함 |
| 로그인 실패 코드 | 400 `bad_credentials`(없는 아이디와 틀린 비밀번호가 같은 응답) — 앱은 401 을 API 토큰·세션 끊김에만 씀. 같은 순간의 가입·이메일 변경이 유일 색인에 걸리면 409(3차 — 500 이면 Postgres 오류 detail 에 이메일이 로그로 남을 수 있었다) |
| 로그 | 아이디·이메일·비밀번호·토큰을 적지 않음. `?session=` 은 `[redacted]`. 앱 오류 보고(앱 `scrubText`·서버 `scrub`)도 `gzs1_…`·`?session=` 을 지움(보강) |

## 2. 표 (마이그레이션 12 — 새 표만, 백업 포함 `users` → `sessions` · 마이그레이션 13 — `devices.session_id` 한 칸)

- 백업을 되살리면 바꾼 비밀번호·로그인이 그대로(테스트). 주인이 없는 옛 백업이면 켤 때 1111 로 만든다.

## 3. 경로 정책 (`backend/src/auth/routePolicy.ts`)

- **공유(18)** — 로그인한 누구나: 플래그, 장 상태·지수·지수 봉, 발견 순위·테마 목록·테마, 종목 검색, 종목 상세(가림), 시세, 봉, AI 분석(새로 만들기 무시·사람마다 하루 10건), 뉴스(가림), 지표 점수, 시장 요약 목록·최신·한 건(가림), 앱 오류 보고.
- **가림**: 종목 상세·뉴스는 등록 표를 보지 않는 미리 보기(주인이 등록한 종목도 등록 안 한 종목과 바이트까지 같음), 시장 요약은 `data.holdings=null` 로 두고 **요약 글을 보유 없이 data 에서 다시 만든다**(3차 — 저장된 글에서 지금 문구와 같은 줄만 빼면 문구가 바뀐 예전 요약의 주인 종목 이름이 샜다), 안내(notes)는 시장 전체 것만 남김(모르는 안내는 뺌). 시세 `fresh=1` 은 주인만(3차).
- **인증(7)**: login·signup·me·logout·logout-all·password·email(PUT).
- **주인 아닌 계정의 시세·상세 (5차 M2)**: 시세의 세션 칸(`session.eligible`·`halted` — 주간거래·NXT·ETP·거래정지 자격)은 종목별 캐시(토스 웹 `sessionFacts` — 주인 잔고 조회가 늘 채움)에서만 알고, 초록 점(`realtime`)·`live`·가격은 토스 웹소켓(주인 등록 종목만 구독)과 3초 갱신 가격 변화를 쓴다 → 4차까지는 주인 아닌 계정이 `/api/stocks/:code/quote`·`/api/stocks/:code` 를 부르면 주인 등록 종목만 eligible 이 true/false, 처음 보는 종목은 null 로 갈렸다. 이제 주인 아닌 계정에게는 **장 달력만으로** 세션을 계산하고(자격은 늘 null), 웹소켓 체결·가격 변화 증거를 쓰지 않는다(`getQuote(code, { shared: true })`). 테스트: 같은 시계·같은 출처로 '주인이 등록·조회·점수 계산해 둔 서버'와 '처음 보는 서버'를 띄워 주인 아닌 계정의 시세·상세·차트·점수·뉴스 본문이 같은지(`accountsOracle`, 고치기 전 코드에서 실패 확인).
- **주인 아닌 계정의 공유 응답 (4차 M2)**: 공유 캐시(분석·지표 점수·시세·봉)는 주인이 먼저 열었거나 장 마감 뒤 주인 등록 종목을 미리 계산해 둔 것일 수 있다 → 그 시각·상태로 주인 종목이 드러나지 않게, 주인 아닌 계정에게는 분석 `id`·`createdAt`·`cached` 를 요청 시각 값(0 · 지금 · false)으로, 지표 점수 `computedAt` 을 지금으로·가치 `asOf.fetchedAt`(재무 받은 시각)은 빈 값으로, 서버 처리 시간 머리글(`Server-Timing` — 캐시 적중이 빠른 것이 보임)은 주지 않는다. 하루 한도도 **캐시에 있든 없든 서로 다른 것 수로** 센다: AI 분석 종목·종류 10개, 지표 점수 종목 30개(오늘 본 것은 다시 봐도 세지 않음, 넘으면 429 `ai_daily_limit`·`score_daily_limit`) — 새로 만드는 것만 세면 한도를 다 쓴 뒤 '캐시에 있으면 200·없으면 429'로 주인 종목을 알아낼 수 있었다. 5차: 지표 점수 가치 칸(미국·한국 간이 #94)의 '지난 값 M/D' 배지와 '…에 받은 값' 안내에서도 날짜를 뺀다. 테스트: 주인이 캐시를 만든 종목과 처음 보는 종목의 응답이 이 칸들에서 같음(`backend/test/accountsOracle.test.ts`). **남는 것 — 응답 속도는 강한 신호다 (5차에서 정확히)**: 주인 등록 종목은 서버가 시세(잔고 조회)·봉(`warmCandles`)·점수(장 마감 뒤 `runDaily`)·재무를 미리 받아 두어 캐시에 있고, 처음 보는 종목은 첫 요청 때 출처에서 받는다 → 검증 실측으로 시세 약 2ms 대 410ms, 봉 1ms 대 410ms. `Server-Timing` 을 빼도 폰이 직접 시간을 잴 수 있고, 1분 240번 제한이면 계정 하나로 코스피 전체를 약 15분에 훑어 **주인 보유 종목 목록을 꽤 정확히 알아낼 수 있다**. 같은 까닭으로 첫 응답의 모양도 갈릴 수 있다(시세 기준 시각이 방금인지, 가치 점수가 '계산 준비 중'으로 시작하는지 — 주인 등록 종목은 재무를 미리 받아 둠). 수량·평단·메모·손익은 나가지 않는다. A단계는 초대한 가족·지인만 가입한다는 전제로 이 신호를 남기고(모든 공유 응답을 느리게 맞추면 가입자 화면이 늘 0.5초 넘게 늦어지고, 그래도 느린 출처 응답과는 구별된다), **B단계에서 사람마다 캐시를 나누거나 공유 캐시를 주인 등록과 상관없이 미리 채워** 없앤다. 그 전에는 모르는 사람에게 가입을 알리지 않는다.
- 시장 요약: data 를 읽지 못한 옛 행은 저장된 글(내 종목 줄이 있을 수 있음)을 주지 않고 빈 요약(실패 행의 고정 문구만 그대로, 4차).
- **개인(49)** — 주인만: 목록 밖 전부. 주인 아닌 계정의 읽기 중 잔고·브리핑·계좌 브리핑·가격 알림·거래량·기기·스냅샷·체결·매매 기록·점수 기록은 빈 값 200, 나머지 403 `personal_data_not_ready`, `/api/admin/*` 는 403 `owner_only`. 웹소켓 스트림도 업그레이드 전에 403.
- **새 경로가 새지 않게**: `test/routePolicy.test.ts` 가 등록된 모든 `/api` 경로(74)를 공유·인증·개인 중 정확히 하나로 세고(새 경로를 만들면 실패), `/api` 밖 경로(`GET /`·`GET /health`·CORS `OPTIONS *` — `OUTSIDE_API_ROUTES`)도 세어 주인 아닌 계정·세션 없음·끊긴 세션의 `/health` 칸이 공유 칸(`SHARED_HEALTH_KEYS`)뿐인지 확인한다(보강 — 예전에는 `/health` 가 관문 밖이라 주인 토스 계좌 합계가 새었다). 주인 데이터에 표시(메모·종목 이름·푸시 토큰)를 심어 주인 아닌 계정으로 모든 GET 을 불러 표시 0, 모든 쓰기 403·표 행 수 그대로, 세션 없는 요청은 모두 403 을 확인. 목록에 넣지 않은 경로는 서버가 기본으로 막는다.
- 끊겼을 때 데이터 절약(pollSaver)의 옛 본문 기억은 보는 사람마다 나눈다.

- 계정이 바뀌면(다른 사람으로 로그인·로그아웃·세션 끊김) **세션을 바꾸는 그 자리에서, 화면을 다시 그리기 전에** react-query 캐시·기기 저장 캐시·조건부 요청 기억을 비움(`lib/session` `onAccountChange` → `components/AuthBridge.tsx`, 보강 — 예전에는 탭을 그린 뒤 비워 앞 사람 잔고가 한 번 보일 수 있었다). 위젯이 적어 둔 개인 데이터(마지막 잔고·마지막 `/api/widget` 응답·그린 데이터)도 지우고 위젯을 '로그인 필요'로 다시 그림(`_layout`). 위젯 스스로도 401 `session_invalid`·403 `session_required`·403 `personal_data_not_ready` 를 받으면 마지막 잔고로 그리지 않고 지움. `/api/auth/me` 는 켤 때 한 번 + 앞으로 돌아왔을 때 6시간 넘었으면. 받은 플래그를 기기에 적는 것은 설정(서버 주소)을 다 읽은 뒤에만.
- 알림(보강): 로그아웃은 서버 등록만 빼고 기기 토큰(알림을 켜 둔 기록)은 남김 → 주인으로 다시 로그인하면(또는 비밀번호를 바꾸면) 새 세션으로 다시 등록(`rebindPush`). 인터넷이 끊긴 채 로그아웃해 서버에 알리지 못한 세션은 기기에 적어 두고(`auth.pendingLogout.v1`) 켤 때·돌아올 때 그 토큰으로 다시 알림.
- 주인 아닌 계정 화면 (4차): 잔고 탭 빈 칸은 차분한 안내 '지금은 시장·종목 정보를 볼 수 있어요' + [시장·종목 둘러보기](발견 탭) 하나. 설정은 주인만 쓰는 줄(수수료·세금 차감 평가·잔고 정렬·잔고 표시·홈 화면 위젯 갱신·위젯 종목 금액·매매 기록·앱 스트리밍·처음 사용 안내 다시 보기)을 숨기고 알림 설정을 묻지 않는다(서버는 403). 플래그가 꺼져 있어도(비상 모드) 지금 서버에 주인 아닌 계정 세션이 있으면 설정 '계정' 칸에 아이디와 안내 한 줄만('로그인 기능이 잠시 꺼져 있어요. 다시 켜지면 여기에서 로그아웃할 수 있어요.' — **5차: [로그아웃]을 뺐다**. 비상 모드에서 로그아웃하면 서버는 404 라 세션을 끊지 못하고 앱만 세션을 잊어, 그 뒤 요청이 API 토큰만 = 주인이 되어 그 폰에 주인 잔고가 보였다. 비밀번호·이메일 바꾸기도 서버가 꺼 두어 뺌).
- 위젯 (5차): '로그인 필요'(자동 로그인 끔·로그인 전·세션 끊김)와 '개인 종목 기능은 준비 중'(주인 아닌 계정)은 **실패가 아니다** — 머리에 '갱신 실패'를 붙이지 않고, 메모 줄에 같은 말을 되풀이하지 않고, 본문은 '로그인하면 보여요 · 눌러서 앱 열기'(잔고·자산·브리핑 위젯 — 예전 잔고 위젯의 '잔고를 불러오지 못했습니다. ↻ 로 다시 시도'·브리핑의 '↻ 로 다시 시도' 대신). 백그라운드 작업·↻ 기록은 '건너뜀', 연달아 실패로 세어 위젯을 다시 그리지 않는다. 처음 비밀번호 권유 시트는 로그인 화면과 같은 어두운 색·금색 버튼(앱 테마와 상관없이). 로그인이 잠기면 서버가 준 남은 시간으로 'N분 뒤에 다시 해 주세요'.
- 주인 아닌 계정 화면(보강): 브리핑 탭 빈 칸은 '종목 브리핑은 준비 중이에요'(종목 추가 말·버튼 없음), 종목 상세의 [관심 추가]·아래 막대 별 버튼 없음, 종목 검색의 '등록' 칸 없음(누르면 상세). 3차: 비중 화면 딥링크는 준비 중 안내(잔고를 받지 않음), 위젯은 '개인 종목 기능은 준비 중'(로그인 필요 아님), 플래그가 꺼져도 지금 서버(관문이 알려 줌 — `noteActiveServer`)에 주인 아닌 계정 세션이 있으면 안내 띠.
- 3차·4차: 로그인 관문은 **설정(서버 주소)을 다 읽은 뒤 그 서버 주소로** 기능 플래그를 이번 실행에서 한 번 새로 받는다(`freshFeaturesOnce` — 저장 캐시 30초를 믿지 않게. 3차에는 설정을 읽기 전 번들 기본 주소로 받아, 진짜 주소의 되살린 캐시를 그대로 믿을 수 있었다). '서버 설정'은 저장한 주소·토큰으로 직접 연결을 확인해 새 주소 캐시에 넣는다(`lib/serverCheck`), 토큰을 바꾼 뒤의 캐시 다시 받기는 그리기 효과가 끝난 뒤에. 자동 로그인을 끈 세션이면 잔고 캐시를 기기에 적지 않는다(`persistsPersonal`).
- 화면: 로그인(늘 다크 — `tokens.ts` `authColors`·`authLayout`·`authFont`), 회원가입, 서버 설정(설정 탭의 `ApiUrlForm` 을 떼어 같이 씀), 비밀번호 바꾸기, 설정 '계정' 칸, 권유 시트, 주인 아닌 계정 안내 띠(잔고·브리핑 탭), 첫 실행 안내는 로그인 뒤·주인에게만.
- 배치(hero-spec 4장, `lib/loginHero.ts` `heroLayout`): 창 폭 840 이상이고 가로가 더 길면 두 칸(왼쪽 그림 W−420 · 오른쪽 입력 356), 그 밖은 한 칸(옆 여백 24/32, 입력 최대 420 가운데, 그림 높이 (H−안전 영역)×0.40 을 240~380 — 명세 0.42 에서 줄여 360×752 폰에서 '서버 설정'·고지 문구까지 한 화면). 남는 높이는 입력 묶음 위 40%·아래 60%. 한 칸의 그림 칸(plot)은 입력 칸과 같은 폭·왼쪽 끝(보강 — 704×933 에서 로고·차트·입력 칸 왼쪽 끝이 한 줄). 키보드가 떠도 **배치는 그대로**(보강 — 예전에는 그림을 72dp 로 접어 입력 묶음이 한순간에 약 230dp 뛰었다): 키보드 높이만큼 아래를 비우고 누른 칸이 키보드 위에 오도록 부드럽게 스크롤해 그림을 위로 밀어냄(비밀번호 칸은 [로그인] 버튼까지, `revealScrollY`). 키보드가 내려가면 먼저 부드럽게 제자리로 스크롤한 뒤 빈 곳을 없앰.

### 4.1 로그인 첫 화면 그림 (`components/auth/LoginHero.tsx`, 기하·시간표 `lib/loginHero.ts`)

- 4.2초 한 번 (3차 시간표, 4차: 0.1초 뒤 시작 · 불기둥은 세로 빛 기둥): 눈금(0~0.3초) · 금색 '가즈아 불기둥'(0.2~0.8초, 감속·8dp 아래에서 제자리로)·금색 선(0.45~0.8초, 왼쪽부터)·부제 '시세 · 브리핑 · 지표'(0.5~0.8초) · 횡보 봉 16개가 70ms 간격으로 나타나며 커짐(0.15~1.5초) → 빨간 상한가 봉 10개가 205ms 간격으로 시가(아래)에서 위로 자라 계단(1.5~3.6초, 윗꼬리 없음 · 다 자라면 천장 띠) → 절정: 붉은 빛(2.6~4.2초)과 마지막 봉에서 위로 솟는 불기둥 하나(3.6~4.2초, 아래 끝 기준으로 자람). 그 뒤 빛·불기둥만 3.6초에 한 번 밝기 1 → 0.82 → 1(숨쉬기). 모든 요소는 나타나기만 하고 사라지지 않음(깜빡임 없음).
- 보강: 빛(glow·glow2)은 **2.6초**부터 켜짐(명세 1.5초 — 봉이 아직 바닥에 있는데 빈 오른쪽 위가 먼저 붉어졌다).
- **3차 (검증 지적, 작은 제품 결정이라 추천안으로 정함)**: ① 로고·금색 선·부제는 **0.2~0.8초에 먼저**(감속, 8dp 아래에서 제자리로 — 예전 명세 3.7초는 첫 3.7초가 '빈 차트를 불러오는 중'처럼 보였다). 3.6~4.2초 절정에는 빛·불기둥만 켜진다 ② 불기둥은 **마지막 상한가 봉 하나에서 솟는 기둥**: 아래 끝은 몸통 폭으로 몸통 뒤(종가 + 최대 3dp)에서 시작해 아래 20% 높이까지 1.3배로 조금 부풀었다가 위로 가늘어져 뾰족하다. 둘레 옅은 주황 빛(타원) · 기둥(주황-노랑 → 붉게 옅어짐) · 가운데 심(거의 흰 크림 `#FFF1D6`, 불투명도 0.95). 예전 세 봉 위 타원 불꽃은 봉에서 떨어진 갈색 얼룩(가운데 약 19% 불투명)·촛불처럼 보였다. 웹 캡처 밝기: 가운데 220 · 바깥 40 ③ 로고 묶음 높이(±8dp)에 걸리는 눈금은 그리지 않는다(금색 선과 1~2dp 어긋나 보였다 — 로고 옆 눈금의 왼쪽 부분 `gridLead` 도 뺌) ④ 마지막 종가는 그림 칸 위 0.18(예전 0.12), 불기둥 높이 0.17 — 불기둥 위 끝이 그림 칸 안·상태 표시줄 아래 ⑤ 봉 몸통·꼬리 자리·폭과 눈금 y 를 `PixelRatio.roundToNearestPixel` 로 화면 픽셀에 맞춤(폴드 dpr 2.625 에서 몸통 24/25px·꼬리 2/3px 로 봉마다 굵기가 달라 보였다 — 폭은 한 번만 맞춰 모든 봉이 같음) ⑥ 숨쉬기를 멈출 때 가까운 끝(밝기 1)까지 0.18초 네이티브 timing(예전 `setValue(0)` 은 최대 18% 튀었다) ⑦ 입력 칸 바탕을 거의 불투명한 어두운 남색으로(두 칸 화면에서 붉은 빛이 칸 왼쪽 절반만 물들였다).
- 움직임은 UI 스레드: RN Animated 네이티브 드라이버의 시계 하나(0 → 4200ms) + 숨쉬기 하나에 요소마다 `interpolate`(감속은 점 7개)로 opacity·translate·scale 만 잇는다. 프레임마다 JS 일 없음, SVG 속성은 움직이지 않음. 봉은 보통 View(상한가 몸통만 expo-linear-gradient), 빛·불기둥·로고는 react-native-svg. reanimated 는 1.4.0 APK 에서 앱이 한 번도 쓰지 않아 OTA 로 처음 쓰지 않는다(명세 7.1). 모두 APK 에 이미 있는 부품 — 새 APK 필요 없음.
- **5차 (검증 지적)**: ① **보이는 기둥을 몸통보다 넓게** — 4차 기둥은 그리는 칸만 몸통의 2.8배였고, 붉은 옆빛이 같은 색 원형 빛에 묻혀 **실제로 보이는 것은 몸통의 약 0.4배(3~4dp) 흰 선**(심지·광선검처럼 보임)이었다(4차 요약의 '폭 2.8배'는 그리는 칸 기준이라 틀렸다). 이제 그리는 칸 몸통 × 3, 가운데 따뜻한 흰 심 몸통 × **1.8** 이고 가운데 0.28~0.72 가 **평평**(0.9~0.95), 옆빛은 0.22~0.78 을 **주황 `pillarWarm` 0.7~0.88**(붉은 원형 빛에 묻히지 않게). 웹 캡처 가로 밝기(4.2초, 기둥 높이 20·40·60·80% 지점): **반폭(FWHM) 몸통의 1.5~1.6배**(360 위쪽만 1.46), 최고점 20% 폭 약 2배 — 봉 위로 곧게 솟는 빛 기둥 ② 위 끝은 **위 안전 영역(상태 표시줄) 아래에서 멈춤**(4차는 그림 영역 위 끝 0 까지 올라가 360·475 에서 기둥 위 31% 가 배터리·신호 아이콘 자리에 꽂혔다 — 웹 캡처는 안전 영역이 0 이라 못 보임). 그래서 마지막 종가를 0.18 → **0.25** 로 내려, 한 칸 360×752(위 28)에서 상태 표시줄 아래로 보이는 기둥이 약 **0.3h(76dp)**, 704×933 0.29h ③ 아래 끝은 몸통 뒤 min(5, 몸통 × 0.35) — 봉 위에 틈이 보이지 않게 ④ 횡보 봉 묶음은 가장 낮은 저가를 띠 아래 끝에(바닥선과 6dp — 예전 약 18dp 떠 있었음), 가로 눈금이 윗꼬리 끝을 가로지르지 않음(약 290개 크기 테스트). 봉 크기는 그대로.
- **4차 (검증 지적, 작은 제품 결정이라 추천안으로 정함)**: ① **불기둥 = 세로 빛 기둥**: 마지막 종가에서 그림 영역 위쪽으로 곧게(그림 칸 h × 0.36, 그림 영역 위 끝에서 멈춤 — 한 칸 폰에서는 0.3h 쯤), 폭은 몸통의 2.8배로 위아래 같고(부풂 없음) 끝이 뾰족하지 않게 위로 갈수록 투명. 가로로는 양옆 투명 → 붉은 빛(`pillarRed`) → 가운데 따뜻한 주황(`pillarWarm`), 가운데 심(몸통 폭 × 0.9)은 따뜻한 흰색(`pillarCore`). 심은 몸통 바로 위에서는 옅고 조금 위에서 가장 밝다(아래 크림 심지 없음). 모양 선 없이 가로 그러데이션 사각형 둘을 세로 가림(`Mask`, 흰색 불투명도)으로 옅게 — 흐림 필터 없음. 움직임은 세로 크기(아래 끝 기준)·불투명도만(네이티브 드라이버). 기기에서 가림 그림이 이상하면 `PILLAR_COLUMN` 하나로 끄면 붉은 빛만(아이콘 A 처럼). 웹 캡처: 933×704 에서 봉 위로 약 159dp 솟는 빛 기둥, 가운데 밝기 − 바깥 약 160 ② 횡보 띠 높이 0.14 → **0.2**, 횡보 봉 불투명도 55% → **70%**(납작한 점처럼 보였다) ③ 상한가 천장 띠 1.5dp → **화면 한 픽셀**(픽셀에 맞춘 몸통 위 끝 — 굵은 크림 띠로 보였다) ④ 첫 재생 시작 0.22 → **0.1초**.
- 언제 움직이나: 앱을 켠 뒤 처음 보일 때 한 번(0.1초 뒤 — 첫 그리기가 끝나고, 4차), 그 뒤(로그아웃 뒤 등)는 마지막 장면 + 숨쉬기. **눌러도 다시 재생하지 않는다**(보강 — 예전 '누르면 다시 재생'은 명세에 없었고, 한 번 잘못 누르면 로고·봉이 한순간에 사라졌다가 3.7초 뒤에야 돌아왔다). '애니메이션 줄이기'면 처음부터 마지막 장면(숨쉬기 없음, 도중에 켜도 바로 멈춤). 앱이 뒤로 감·창 크기 바뀜(접기·펴기)이면 마지막 장면으로. 숨쉬기는 한 칸에서 키보드가 떠 그림이 밀려났을 때와 회원가입·서버 설정이 위에 올라와 가려졌을 때(`useIsFocused`) 멈춤(재생 중이면 끝까지 둔다 — 그림이 한순간에 바뀌지 않게). 입력은 그림과 상관없이 처음부터 됨.
- 겹침 없음: 로고 묶음 높이(±8dp)에 걸리는 눈금은 그리지 않음, 상한가 봉은 로고 묶음(+8dp)과 겹치지 않음, 불기둥은 그림 영역 안·상태 표시줄(위 안전 영역) 아래(5차), 가로 눈금은 횡보 봉을 가로지르지 않음(5차), 로고 묶음은 그림 영역 안(한 칸은 그림 아래 끝 위 · 두 칸은 오른쪽 입력 칸 왼쪽). `test/loginHero.test.ts` 가 약 290개 창 크기 × 0~4.2초 50ms 마다 확인, 네 크기에서 봉 폭·자리가 화면 픽셀 위(dpr 2.625)인지도.
- 화면 읽기: 그림은 꾸밈이라 건너뜀, 로고만 '가즈아 불기둥' 머리글. 그림 안에 누르는 곳은 없다.
- 금색 글자는 SVG 세로 그러데이션(`WORDMARK_GRADIENT` 하나로 단색으로 바꿀 수 있음 — 기기에서 이상하면).

## 5. 배포 순서·되돌리기

0. **병합 준비 (끝남, 3차)**: 최신 main(60ec3b7 — #88 이름·아이콘·APK 1.5.0, #89 차트 최고·최저, #90 가치 점수, #91 토스 앱 열기)을 합쳤다. 겹친 16개 파일(설정 탭·featureService·features 테스트·app.ts·migrate·schema·backupService·postgres·tossSyncSafety·tradeRecords 테스트·types·종목 상세·tokens·문서 3개)은 양쪽을 남겼고, 마이그레이션은 main 의 11 다음 **12·13**. 병합 전 PR CI 의 Postgres 테스트(REQUIRE_PG=1 — 이 PC 에서는 건너뜀) 통과를 확인한다.
1. 병합. 병합 뒤 앱 버전은 1.5.0 → OTA 는 **APK 1.5.0 이 깔린 폰에만** 간다. 폰의 설정 > 앱 업데이트 '현재 버전'이 1.5.0 인지 먼저 본다(아니면 1.5.0 APK 설치가 먼저 — 사용자에게 알림).
2. **앱 OTA 먼저** — 서버가 아직 플래그를 안 주므로 변화 없음. 폰에서 앱을 껐다 켜 새 묶음을 받고, 설정 > 앱 업데이트에서 새 묶음으로 도는지 확인한다. **서버의 `accounts` 는 기본 켜짐이라, 새 묶음이 없는 앱은 서버 배포 뒤 모든 개인 경로가 403 `session_required` 이고 OTA 로도 고칠 수 없다** → 확인 전에는 3 으로 가지 않는다(서두르면 Railway 변수 `ACCOUNTS_DISABLED=1` 로 먼저 배포하고, 확인 뒤 변수를 지운다).
3. 서버 배포 — 마이그레이션 12·13, 주인 시드, 플래그 켜짐 → 앱이 1분 안에 로그인 화면 → '서성원'/처음 비밀번호 → 비밀번호 변경. **가능하면 첫 배포 전에 Railway 변수 `OWNER_INITIAL_PASSWORD` 를 넣어 둔다**(공개 저장소의 1111 이 처음부터 통하지 않게 — 넣었으면 그 값으로 로그인).
4. 확인: 위젯·백그라운드 알림이 계속 오는지(자동 로그인 켬 — 로그인 뒤 알림 등록이 새 세션에 다시 묶인다), 설정 맨 위 '처음 비밀번호를 쓰고 있어요' 띠가 사라졌는지(`/health` 는 이제 이 값을 내보내지 않는다).
5. 문제 시 (비상 모드 — 5차: 앱은 비상 모드에서 주인 아닌 계정의 [로그아웃]을 보이지 않고 세션을 계속 보낸다 → 세션이 남은 가입자 폰은 계속 막힘): 주인 세션으로 `PUT /api/admin/features {"accounts": false}`, 로그인이 안 되면 Railway 변수 `ACCOUNTS_DISABLED=1`(앱에도 플래그를 꺼짐으로 줌). 앱은 OTA 되돌리기(`docs/OTA-되돌리기.md`). **운영 규칙 (4차): 가입자가 한 명이라도 있으면, 비상 모드를 켜기 전에 ① Railway 변수 `API_TOKEN` 을 새 값으로 바꾸고 ② 새 값은 주인 폰에만 넣는다(설정 → 서버 연결 → API 토큰 → 저장하고 연결 확인)** — 비상 모드에서는 계정 전처럼 세션 머리글이 없는 요청이 API 토큰만으로 주인이 되기 때문(API 토큰은 앱 묶음 안에 있어 모든 가입자 폰에 있다). 막는 것·못 막는 것은 1장 '비상 모드' 줄: 주인 아닌 계정의 세션(살아 있음·기한 지남·끊김)을 보낸 요청만 그 계정으로 막고(테스트 `accountsMatrix`), 로그아웃·다시 설치한 가입자 폰, API 토큰을 꺼낸 사람, 세션 확인 DB 오류는 막지 못한다. 끈 채로 오래 두지 않는다. 비상 모드를 풀 때 옛 토큰으로 돌리면 가입자 폰도 다시 연결되고(계정 모드라 개인 데이터는 막힘), 새 토큰으로 두면 가입자는 새 앱 묶음이 필요하다.
6. 누가 먼저 1111 로 들어와 비밀번호를 바꿨다면: Railway 변수 `OWNER_RESET_PASSWORD=<새 비밀번호>` 로 다시 배포 → 주인 비밀번호가 그 값으로 바뀌고 주인 세션·알림 기기가 모두 끊긴다 → 로그인. 같은 값은 한 번만 적용되므로 변수를 남겨도 다시 로그아웃되지 않지만, 쓴 뒤 지우는 것을 권한다.

## 6. 알아 둘 한계 (A단계)

- API 토큰은 앱 묶음(`EXPO_PUBLIC_API_TOKEN`) 안에 있어 마음먹은 사람은 꺼낼 수 있다 → 1111 은 알려진 비밀번호이므로 빨리 바꾼다. B단계 전에는 다른 사람에게 토큰을 주지 않는 것을 권한다.
- 자동 로그인을 끄면 앱을 닫은 뒤 위젯·백그라운드 알림이 개인 데이터를 받지 못한다(세션이 메모리에만 있음). 잔고 캐시는 기기에 적지 않지만(3차), 위젯이 이미 그려 둔 잔고는 앱을 닫은 뒤 **다음 위젯 갱신(최대 약 30분) 때** 지워진다(그때 서버가 403 → 개인 데이터 지움). 공용 폰이면 앱에서 [로그아웃]을 누르는 것이 가장 확실하다.
- 잠금·속도 제한은 서버 메모리라 재배포하면 초기화된다(지금 Railway 1대).
- Android 자동 백업에 AsyncStorage(세션 토큰 포함)가 들어갈 수 있다 → 다음 APK 때 `android.allowBackup: false` 검토.
- 비밀번호 찾기(메일 서비스)·회원 탈퇴·로그인 기기 목록은 아직 없다. 주인만 비상 되돌리기(`OWNER_RESET_PASSWORD`)가 있다.
- 잠금은 아이디 + IP 라(4차) 남이 다른 IP 에서 주인 아이디를 틀려도 주인의 새 로그인은 막히지 않는다. 다만 여러 IP 로 합쳐 **10분 안에** 50번 틀리면 그 아이디 전체가 10분 막힌다(5차 — IP 10곳 넘게 필요)(이미 로그인한 기기와 그 기기의 비밀번호·이메일 변경은 그대로 — 3차). 같은 통신사 NAT(같은 공인 IP)를 쓰는 사람이 틀리면 그 IP 의 주인 로그인도 10분 막힐 수 있다.
- 자동 로그인을 끄면 위젯·백그라운드 알림은 앱이 떠 있어도 개인 데이터를 보이지 않는다('로그인하면 보여요' — 4차, 위젯은 '갱신 실패'가 아니라 조용한 안내 — 5차). 푸시도 오지 않는다(5차).
- 계정을 켠 뒤에는 주인이 새 세션으로 로그인해야 푸시가 간다(세션 없이 등록한 옛 기기에는 보내지 않음 — 4차). 배포 직후 주인이 로그인할 때까지는 알림이 멈출 수 있다.
- 주인이 처음 비밀번호(1111)를 쓰는 동안에도 가입은 열려 있다(가입을 닫아도 1111 로 주인 로그인은 막지 못함 — 첫 배포 전 `OWNER_INITIAL_PASSWORD` 가 가장 확실). 분석·지표 점수 응답의 캐시 시각·상태는 4차, 시세의 세션 자격·웹소켓 상태는 5차에서 주인 아닌 계정에게 가렸다. **응답 속도(캐시 적중)는 강한 신호로 남는다** — 마음먹은 가입자는 주인 보유 종목 목록을 알아낼 수 있다(3장). B단계 전에는 모르는 사람에게 가입을 알리지 않는다.
- 속도 제한(공유 경로 1분 240번 포함)은 서버 메모리라 재배포하면 초기화된다.
- 폰에서 아직 못 본 것(웹 캡처·테스트만): 키보드가 뜰 때의 부드러운 스크롤, react-native-svg 안드로이드의 가림(Mask) 불기둥(이상하면 `PILLAR_COLUMN` 끔 — 붉은 빛만), 삼성 글꼴의 금색 그러데이션 글자, 933×704 빛 층 하드웨어 텍스처 60fps(개발자 옵션 GPU 막대). 이상하면 `WORDMARK_GRADIENT` 로 단색 로고.

## 7. B단계 계획 (요약)

1. 표마다 `user_id`(`registered_stocks` 는 PK `(user_id, code)`, 기존 행은 주인), 개인 `meta` 키는 `user_meta`로. 서비스 메서드에 `userId`.
2. 사람마다 토스 키 — AES-256-GCM(`CREDENTIALS_KEY`), 복호화는 쓸 때만. 토스 Open API 약관(다른 사람 키를 서비스가 대신 쓰는 것) 확인이 먼저.
3. 푸시 기기·위젯·스트림을 사람별로 (세션 없는 요청(API 토큰만)의 개인 데이터 0 은 A단계 4차에서 이미 — 비상 모드 빼고).
4. 종목 브리핑 = 공유 본문(보유 정보 없음) + 사람별 보유 덧붙임(코드 계산) → 모델 호출 수가 사람 수에 비례하지 않게. 사람별·전체 AI 비용 상한.
