# 계정·로그인·회원가입 설계 (3-45)

- A단계 구현 2026-09-28 (서버 `backend/src/auth/*`·`routes/auth.ts`, 앱 `lib/session.ts`·`app/login.tsx`·`app/signup.tsx` 등). 플래그 `accounts`(서버 기본 켬, 앱 fallback 꺼짐).
- 새 APK 필요 없음 (OTA + 서버 배포). 새 네이티브 모듈·package.json 변경 없음 — 세션은 AsyncStorage(`expo-secure-store` 는 APK 에 없음).
- 로그인 첫 화면 그림·움직임은 따로 적은 명세(hero-spec)를 따른다. 이번 단계는 같은 크기의 멈춘 그림(`components/auth/LoginHero.tsx`)이고 움직임은 다음 작업.

## 0. 쉬운 요약

1. 아이디로 로그인한다. 지금까지의 데이터는 모두 아이디 **'서성원'** 것이다. 처음 비밀번호는 **1111** 이고 설정에서 바꾼다(강제하지 않음 — 로그인 직후 한 번 권유, 설정 맨 위 띠).
2. 회원가입은 네 칸: 아이디, 비밀번호, 비밀번호 확인, 이메일. 가입하면 바로 로그인.
3. 한 번 로그인하면 거의 풀리지 않는다. '자동 로그인'(기본 켬)이면 1년, 쓰는 날마다 1년이 다시 늘어난다. 인터넷이 끊기거나, 서버가 잠깐 멈추거나, 앱이 업데이트돼도 로그아웃되지 않는다. 로그아웃은 ① 직접 ② 다른 기기에서 '모든 기기에서 로그아웃'·비밀번호 변경 ③ 1년 넘게 안 씀 뿐.
4. 새로 가입한 사람은 서성원님 데이터를 볼 수 없다 — **서버가 막는다**. A단계에서 새 계정은 시장·종목 정보만 본다.
5. 새 계정도 자기 종목을 쓰게 하는 것은 B단계(표마다 '누구 것인지' 칸, 토스 키 사람마다 암호화).
6. 문제가 생기면 끌 수 있다: 플래그를 끄면 지금과 똑같다. 로그인이 안 돼 관리 API 를 못 쓰면 Railway 변수 `ACCOUNTS_DISABLED=1`.

## 1. 결정

| 항목 | 결정 |
|---|---|
| 주인 계정 | `서성원`(NFC), 처음 비밀번호 `1111`, `is_owner=1`, `initial_password=1`. 서버를 켤 때 주인이 없을 때만 만든다(`insert … on conflict do nothing`). 있으면 절대 건드리지 않음. `OWNER_LOGIN_ID`·`OWNER_INITIAL_PASSWORD` 로 바꿀 수 있음 |
| 입구 | API 토큰(Bearer) 확인을 **먼저**, 그다음 세션 `X-Session-Token`(`X-Session` 도 받음, 웹소켓은 `?session=` 도) |
| 세션 없이 여는 경로 | `GET /api/features`, `POST /api/auth/login`, `POST /api/auth/signup` (세션 머리글을 읽지도 않음) |
| 세션 없는 요청 | 403 `session_required` — 401 이 아닌 까닭: 예전 앱은 401 을 'API 토큰 확인'으로 보여 줌 |
| 끊긴·없는·지난 세션 | 401 `{ error: "SESSION_INVALID", code: "session_invalid" }` — **앱이 로그아웃하는 유일한 응답** |
| 세션 DB 오류 | 503 `auth_unavailable` (로그아웃 아님) |
| 자동 로그인 켬 | 기기 저장 `auth.session.v1`, 서버 기한 365일, 쓸 때마다 연장(DB 에는 24시간에 한 번) |
| 자동 로그인 끔 | 메모리만, 서버 기한 12시간, 쓸 때마다 연장(15분에 한 번) |
| 비밀번호 변경 | 이 세션 유지, 다른 세션 모두 끊음, `initial_password=0` |
| 모든 기기에서 로그아웃 | 이 기기 포함(확인 창) |
| 가입 규칙 | 아이디 2~20자 한글 음절·영문·숫자·밑줄(NFC, 대소문자 무시 중복 불가) · 비밀번호 8~64자 영문+숫자, 아이디와 다름 · 이메일 형식(소문자 저장, 중복 불가, 확인 메일 없음). 서버·앱이 `shared/fixtures/authRules.json` 으로 같은 결과 |
| 해시·토큰 | scrypt N=16384 r=8 p=1 64바이트·소금 16바이트(`scrypt$N$r$p$소금$키`), `timingSafeEqual`. 세션 토큰 `gzs1_` + 32바이트 base64url, DB 에는 sha256 만 |
| 잠금·제한 (메모리) | 같은 아이디 5번 틀리면 10분(없는 아이디도 같게 — 계정 유무가 드러나지 않게). IP 별 로그인 10분 20번, 가입 1시간 5번 + 전체 하루 30번, 비밀번호 변경 사용자별 10분 10번. Railway 에서는 프록시 한 단계를 믿음(`TRUST_PROXY_HOPS`) |
| 로그인 실패 코드 | 400 `bad_credentials`(없는 아이디와 틀린 비밀번호가 같은 응답) — 앱은 401 을 API 토큰·세션 끊김에만 씀 |
| 로그 | 아이디·이메일·비밀번호·토큰을 적지 않음. `?session=` 은 `[redacted]` |
| 플래그 끔 | `/api/auth/*` 404, 세션 머리글 무시, 모든 요청이 지금처럼(API 토큰 = 주인) |
| 예전 서버 | 로그인·가입이 우리 서버의 404 면 앱이 이번 실행 동안 로그인 없이(fail-open) |

## 2. 표 (마이그레이션 11 — 새 표만, 백업 포함 `users` → `sessions`)

- `users(id, login_id, login_id_key UNIQUE, email UNIQUE(NULL 여러 개 허용), password_hash, is_owner, initial_password, created_at, updated_at)` + 주인 한 명 부분 유일 색인 `where is_owner = 1`
- `sessions(id, user_id → users ON DELETE CASCADE, token_hash UNIQUE, remember, device_label, created_at, last_seen_at, expires_at, revoked_at)`
- 시각은 `seoulIso()` 글자. 끝난 세션(기한 지남·끊긴 지 30일)은 켠 뒤 1분·하루 한 번 지운다.
- 백업을 되살리면 바꾼 비밀번호·로그인이 그대로(테스트). 주인이 없는 옛 백업이면 켤 때 1111 로 만든다.

## 3. 경로 정책 (`backend/src/auth/routePolicy.ts`)

- **공유(18)** — 로그인한 누구나: 플래그, 장 상태·지수·지수 봉, 발견 순위·테마 목록·테마, 종목 검색, 종목 상세(가림), 시세, 봉, AI 분석(새로 만들기 무시·사람마다 하루 10건), 뉴스(가림), 지표 점수, 시장 요약 목록·최신·한 건(가림), 앱 오류 보고.
- **가림**: 종목 상세·뉴스는 등록 표를 보지 않는 미리 보기(주인이 등록한 종목도 등록 안 한 종목과 바이트까지 같음), 시장 요약은 `data.holdings=null`·'내 종목' 줄·보유/시세 안내 줄을 뺌.
- **인증(7)**: login·signup·me·logout·logout-all·password·email(PUT).
- **개인(49)** — 주인만: 목록 밖 전부. 주인 아닌 계정의 읽기 중 잔고·브리핑·계좌 브리핑·가격 알림·거래량·기기·스냅샷·체결·매매 기록·점수 기록은 빈 값 200, 나머지 403 `personal_data_not_ready`, `/api/admin/*` 는 403 `owner_only`. 웹소켓 스트림도 업그레이드 전에 403.
- **새 경로가 새지 않게**: `test/routePolicy.test.ts` 가 등록된 모든 `/api` 경로(74)를 공유·인증·개인 중 정확히 하나로 세고(새 경로를 만들면 실패), 주인 데이터에 표시(메모·종목 이름·푸시 토큰)를 심어 주인 아닌 계정으로 모든 GET 을 불러 표시 0, 모든 쓰기 403·표 행 수 그대로, 세션 없는 요청은 모두 403 을 확인. 목록에 넣지 않은 경로는 서버가 기본으로 막는다.
- 끊겼을 때 데이터 절약(pollSaver)의 옛 본문 기억은 보는 사람마다 나눈다.

## 4. 앱

- `lib/session.ts`(React 없는 모듈 — 앱·위젯·백그라운드 공용, 저장소는 `lib/sessionStorage.ts` 가 AsyncStorage 를 끼움): 저장·서버 주소 짝(그 서버에만 보냄)·`handleSessionInvalid(보낸 토큰)`(지금 토큰일 때만 지움)·계정 모드 기억(`auth.device.v1`, 토큰 없음)·자동 로그인 선택(`auth.rememberPref.v1`)·fail-open·권유 시트 한 번.
- 머리글: `api/client.ts` 의 요청 전부(로그인·가입 빼고), 위젯·백그라운드(`widgets/data.ts`·`lib/marketSummaryLoad.ts` — 기기 저장 세션), 실시간 스트림(주인 아닌 계정·로그인 전에는 열지 않음).
- 연결 오류 판정(`lib/connectionError.ts`)에서 `SESSION_INVALID`·`SESSION_REQUIRED`·`PERSONAL_DATA_NOT_READY` 는 연결 오류가 아님.
- 관문(`lib/authGate.ts` + `_layout` 의 `Stack.Protected`): 이 서버의 세션이 있으면 바로 앱(인터넷이 없어도), 없고 계정 모드(받은 플래그, 모르면 이 기기가 본 적 있는지)면 로그인·회원가입만. '서버 설정'(`/server`)은 늘 열림. 설정·세션을 읽기 전에는 바꾸지 않음(스플래시가 가림).
- 계정이 바뀌면(로그인·로그아웃·다른 사람) react-query 캐시·기기 저장 캐시·조건부 요청 기억을 비움(`components/AuthBridge.tsx`). `/api/auth/me` 는 켤 때 한 번 + 앞으로 돌아왔을 때 6시간 넘었으면.
- 화면: 로그인(늘 다크 — `tokens.ts` `authColors`·`authLayout`·`authFont`), 회원가입, 서버 설정(설정 탭의 `ApiUrlForm` 을 떼어 같이 씀), 비밀번호 바꾸기, 설정 '계정' 칸, 권유 시트, 주인 아닌 계정 안내 띠(잔고·브리핑 탭), 첫 실행 안내는 로그인 뒤·주인에게만.
- 배치(hero-spec 4장, `lib/loginHero.ts` `heroLayout`): 창 폭 840 이상이고 가로가 더 길면 두 칸(왼쪽 그림 W−420 · 오른쪽 입력 356), 그 밖은 한 칸(옆 여백 24/32, 입력 최대 420 가운데, 그림 높이 (H−안전 영역)×0.42 를 240~380). 남는 높이는 입력 묶음 위 40%·아래 60%. 키보드가 뜨면 그림을 72dp 로.
- 접근성: 누르는 곳 44dp 이상, 화면 읽기 이름 '아이디'·'비밀번호'·'비밀번호 보기'·'자동 로그인'(checkbox, 선택됨)·'로그인'·'회원가입'·'서버 설정', 오류는 칸 아래 글 + 알림 읽기, 글자는 시스템 크기를 따르되 150% 까지(로고는 꾸밈이라 고정).

## 5. 배포 순서·되돌리기

1. 병합.
2. **앱 OTA 먼저** — 서버가 아직 플래그를 안 주므로 변화 없음. 폰에서 새 묶음을 받는다.
3. 서버 배포 — 마이그레이션 11, 주인 시드, 플래그 켜짐 → 앱이 1분 안에 로그인 화면 → '서성원'/1111 → 비밀번호 변경.
4. 확인: 위젯·백그라운드 알림이 계속 오는지(자동 로그인 켬), `/health` 의 `accounts.ownerInitialPassword` 가 false 인지.
5. 문제 시: 주인 세션으로 `PUT /api/admin/features {"accounts": false}`, 로그인이 안 되면 Railway 변수 `ACCOUNTS_DISABLED=1`(앱에도 플래그를 꺼짐으로 줌). 앱은 OTA 되돌리기(`docs/OTA-되돌리기.md`).

## 6. 알아 둘 한계 (A단계)

- API 토큰은 앱 묶음(`EXPO_PUBLIC_API_TOKEN`) 안에 있어 마음먹은 사람은 꺼낼 수 있다 → 1111 은 알려진 비밀번호이므로 빨리 바꾼다. B단계 전에는 다른 사람에게 토큰을 주지 않는 것을 권한다.
- 자동 로그인을 끄면 앱을 닫은 뒤 위젯·백그라운드 알림이 개인 데이터를 받지 못한다(세션이 메모리에만 있음).
- 잠금·속도 제한은 서버 메모리라 재배포하면 초기화된다(지금 Railway 1대).
- Android 자동 백업에 AsyncStorage(세션 토큰 포함)가 들어갈 수 있다 → 다음 APK 때 `android.allowBackup: false` 검토.
- 비밀번호 찾기(메일 서비스 또는 주인 초기화)·회원 탈퇴·로그인 기기 목록은 아직 없다.

## 7. B단계 계획 (요약)

1. 표마다 `user_id`(`registered_stocks` 는 PK `(user_id, code)`, 기존 행은 주인), 개인 `meta` 키는 `user_meta`로. 서비스 메서드에 `userId`.
2. 사람마다 토스 키 — AES-256-GCM(`CREDENTIALS_KEY`), 복호화는 쓸 때만. 토스 Open API 약관(다른 사람 키를 서비스가 대신 쓰는 것) 확인이 먼저.
3. 푸시 기기·위젯·스트림을 사람별로, 그 뒤 세션 없는 요청(API 토큰만)의 개인 데이터 0.
4. 종목 브리핑 = 공유 본문(보유 정보 없음) + 사람별 보유 덧붙임(코드 계산) → 모델 호출 수가 사람 수에 비례하지 않게. 사람별·전체 AI 비용 상한.
5. 관리: 사용자 목록·정지·비밀번호 초기화·세션 목록. 회원 탈퇴·내 데이터 내려받기.
