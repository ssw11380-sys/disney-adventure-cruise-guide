## 구현

### 계좌 원본

- 새 `accountLiveRefresh` 서버 플래그, 기본 켜짐. 인증을 통과한 앱 스트림이 하나라도 연결된 동안만 동작한다.
- 첫 접속에 최신 조회가 없으면 비동기로 시작. 최근 정기·수동·체결 조회 후 30초 이내면 재사용한다. 다음 추가 조회는 완료 후 30초.
- 여러 앱 연결은 한 주기를 공유한다. 기존 동기화가 진행 중이면 겹쳐 조회하지 않는다. 앱이 모두 이탈하면 추가 예약 중지. 진행 중인 저장은 마무리한다.
- 실패 시 1분 → 2분 → 4분 → 최대 5분으로 늦춘다. 재접속으로 대기·최소 간격을 우회하지 않는다. 성공 뒤 30초 복귀.
- 자동 동기화 또는 토스 계좌 표시 기능이 꺼져 있으면 추가 실행하지 않는다. 플래그를 끄면 기존 정기·체결·브리핑·수동 동작만 유지.
- 원본 계좌/보유 종목 조회, 누락 검사, 수량·평단 보호, 원화 장부, 원본 평가 저장 경로를 그대로 사용한다.
- 새 화면용 조회에서 수량 변화가 없으면 부가 대조 이력·전 종목 시세 조회를 추가하지 않는다. 기존 정기·브리핑 경로의 대조는 유지하고, 그 실행이 화면 조회에 합류했을 때도 수행한다.
- 완료 통지를 기존 스트림으로 전달한다. 보고서 생성·시세 전달·일반 GET은 새 작업을 기다리지 않는다.

### 위젯

- `widgetLeanLive` 켜짐일 때 Android가 실제 작업 실행 기회를 주면 휴장 2시간 생략을 하지 않는다.
- 위젯 자체 주기·추가·크기 변경의 응답 재사용은 1분 이내로 제한한다. 연속 위젯 이벤트의 중복 호출은 계속 줄인다.
- 수동 새로고침은 기존처럼 즉시 조회한다. Android 예약 간격, 알림 개수, 네이티브 설정·APK는 변경하지 않는다.
- 플래그 끄기/옛 서버 fallback에서는 기존 15분·휴장 2시간 캐시와 표시를 유지한다.

## 변경 전후 검사

- 고정 시계·가짜 서버/저장소를 이용한다. 운영 자료를 변조하거나 유료 보고서를 생성하지 않았다.
- 변경 전 위젯 조건/실제 조회 경로 5건 실패 → 변경 후 통과. 휴장 백그라운드 호출, 주기·크기 변경 1분 경계, 시계 역행, 기능 끄기를 포함한다.
- 새 화면 조회에 대한 불필요한 대조 방지 1건은 기존 코드 실패 → 수정 후 통과. 정기·브리핑 합류와 실제 수량 변경 시 대조 유지도 검사한다.
- 계좌 제어 7건: 최초 접속, 30초 경계, 최근 조회, 여러 번 접속, 느린 원본, 앱 이탈, 실패 간격, 플래그/자동 동기화 꺼짐, 실행 중 겹침 등.
- 같은 입력으로 정기 조회와 화면 조회의 원액·비용·환산 기준·누락 상태·보유 자료 동일성을 확인하고, 수신 시각은 새 조회 시각으로 전진하는지 확인한다. 최초 테스트 작성 시 가짜 출처의 1초 전진을 놓친 테스트 오류는 정확한 새 시각을 명시해 바로잡았다.
- 앱 전체: 212개 파일, 3,834건 통과. 타입 검사·린트 통과.
- 서버 전체: 120개 파일 2,103건 통과/19건 로컬 PostgreSQL 조건으로 생략. 이후 동일 입력 비교 1건 추가 포함 대상 파일 31건 통과/1건 PG 생략. PostgreSQL 검증은 배포 전 CI에서 확인한다.
- 기대값을 낮추거나 기존 스냅샷을 갱신하지 않았다. 기능 전체 목록 테스트에 새 플래그 기본값만 추가했다.

## 속도·품질 해석

- 30초는 추가 조회 간격 설정이며, 외부 조회·저장·네트워크 시간을 합친 완료 시간을 보장하지 않는다. 원본 API가 갱신하지 않은 금액을 임의로 최신 가격으로 재계산하지 않는다.
- 토스 공식 계좌 REST와 시세/주문 WebSocket은 서로 다른 자료다. 계좌 총액이 토스 앱과 매 순간 완전히 동일하다고 보장하지 않는다.
- 모델·프롬프트·보고서 입력·생성 단계·출력 길이 변경 없음. 동일 입력 계좌 계산/저장 보존 검사는 통과했지만, 유료 모델 생성 결과의 통계적 품질 동일성 실험은 하지 않았다.
- 배포 전 실제 운영 표본: Windows PC → Railway, 2026-10-07 15:46 KST. 원본 캐시 상태 미확정, GET 모두 성공. 계좌 GET 349ms, 위젯 GET 849ms, 조건부 304 131ms. 별도 5초 스트림에서 첫 변경 시세 417ms/15건 수신. 표본이 작고 캐시/시장 상황이 달라 개선율 비교에 쓰지 않는다.
